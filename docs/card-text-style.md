# カード効果の表記ルール

2026-10-07 改定。対象は全360枚（通常カード・生成専用カード・スターター）と、日本語・韓国語・英語の全1080文面。ゲームのバランス版は変更しない。

## 優先順位

1. **解釈を一つにする**：実際の対象・処理順・条件・数値・期限を欠かさない。
2. **理解しやすくする**：主体と対象を明記し、選択・自動・ランダムを区別する。
3. **読みやすくする**：一つの処理を短い節に分ける。必要な条件を消して短くしない。

旧62字／96字の総文字数制限と、長文カードだけの例外枠は廃止する。詳細画面は全文を通常の読める文字サイズで縦に表示する。文字を縮小したり省略したりして収めない。

## 正本と変更手順

文面の正本は `client/src/shared/cardEffectText.ts`。各IDの `ja`・`ko`・`en` を同時に編集する。カード定義の翻訳・調整を終えた後、`standardizeCardTexts()` がこの文面をそのまま適用する。文章から対象や数値を推測する正規表現変換、英語だけの自動短縮、未翻訳時の他言語へのフォールバックは行わない。未登録IDはエラーにする。

確認順は `engine.ts` の実行経路 → 最終カード定義 → 文面。特に `CUSTOM_SPELLS` と拡張カードの専用処理は `act` / `val` より優先される。コードコメントや古い表記だけを根拠にしない。文面監査のためにバランス・対象処理を変更しない。仕様を変更する場合は別の判断と検証を行う。

追加・変更時は三言語で、条件、主体、対象、範囲、枚数、選び方、処理、順序、持続、回数を照合し、監査台帳を更新して `npm run text:check` を実行する。台帳のハッシュ一致はレビュー後の改変を検知するもので、文の意味を自動証明するものではない。

## 基本文型

`【条件／タイミング】主体・対象・選び方 → 処理 → 持続／回数`

- タグは節の先頭。購入条件、召喚条件、発動条件、攻撃条件を混同しない。
- 条件はできる限り効果より先に書く。条件付きの追加効果は、その処理の直前に条件を書く。
- 独立した処理は ` · ` で分ける。詳細画面で改行する。同じ条件が次の節にも続くときは「その後」「成功した場合」などで関係を明記する。
- ダイスの結果表だけは ` — ` の後を ` / ` で区切る。各行は `1-2: 効果`。共通条件は表の前に置き、最後の結果だけに見える位置へ置かない。
- 箇条書き記号だけで「かつ／または／代わりに／さらに」を表さない。全言語で接続関係を保つ。
- 英語は `cost 3-`、`Own 9+ spells`、`1 ally` のような条件の省略を避ける。`purchase cost 3 or less`、`your deck composition contains at least 9 spells` と書く。

## タイミングと期限

| 日本語 | 韓国語 | 英語 |
|---|---|---|
| 召喚条件 | 소환 조건 | Summon Requirement |
| 発動条件 | 발동 조건 | Play Requirement |
| 購入条件 | 구매 조건 | Purchase Requirement |
| 攻撃条件 | 공격 조건 | Attack Requirement |
| 召喚時 | 소환시 | On Summon |
| 発動時 | 발동시 | On Cast |
| 購入時 | 구매시 | On Purchase |
| 自分ターン開始時 | 자신 턴 시작시 | Your Turn Start |
| 自分ターン終了時 | 자신 턴 종료시 | Your Turn End |
| 常時 | 상시 | Passive |
| 永続 | 영구 | Permanent |
| 破壊時 | 파괴시 | On Destruction |
| 攻撃時／攻撃後 | 공격시／공격 후 | On Attack／After Attack |
| クエスト／報酬 | 퀘스트／보상 | Quest／Reward |
| 回数制限 | 횟수 제한 | Use Limit |

- 「毎ターン」だけで済ませない。どちらの、開始時／終了時かを書く。
- 「Nターン」は自分のターンか双方通算かを明記。召喚／発動ターンを含むか、何回後の開始時に切れるかも必要に応じて書く。双方通算の期限を、ターンスキップでずれる「自分のNターン」と言い換えない。
- `常時` は場の発生源・条件が有効な間。`（持続）` は変更を受けたモンスターが場を離れるまで。`このターン終了まで` は一時効果。ゲーム中残る効果は「場を離れても続く」と明記。
- 同名合計／各個体、ゲーム中／各自分ターンを区別する。使い切りの効果と、毎ターン選べる効果を同じ「1回」で表さない。

## 主体・範囲・選択

- 「自分」「相手」はプレイヤー。「このモンスター」「自分の場のモンスター1体」はモンスター。体力・マナ・シールド・雫の受け手が不明にならないようにする。
- 「場の全体」ではなく「両方の場の全モンスター」など、両側か片側か、カード種別を明記。クエストを含まない全体除去はその違いを書く。
- 自分で指定する場合は「選ぶ」。自動選択なら「自動で」と選択基準・同値の優先順を書く。ランダムなら候補の集合を書く。複数回のランダムダメージは毎回選び直すかを明記。
- `N体／枚` と `N体／枚まで` を区別。任意選択は「してよい」または「まで」。不足時に可能な分だけ行う処理では、その扱いを明記する。
- 「異なる個体」は同名でもよい。「N種類」は異なる名前の数。同名以外が条件なら「他の1体」と略さない。
- 「オーラ」など既存の対象制限はキーワード説明も併せて参照する。自動選択の候補から特定の能力を除く場合は個別説明でも明記する。

## ゾーンと生成

| 用語 | 定義 |
|---|---|
| 墓地 / 묘지 / graveyard | 捨てたカードなどを置き、デッキ補充で戻る場所。旧名称シェルフは使わない。 |
| リフト / 리프트 / Rift | 除外カードの場所。墓地と別。通常のデッキ補充には使わない。 |
| デッキ / 덱 / deck | 現在の山札だけ。 |
| デッキ構成 / 덱 구성 / deck composition | デッキ＋手札＋墓地＋場のモンスター。場の魔法・クエスト、リフトを含まない。 |

- 「除外」はリフトへの移動。既存カードの移動と、新しいカードの追加は区別する。
- 移動元・移動先・所有者を明記する。「墓地へ」だけで終えない。
- カード一覧から作るなら「新しい」「生成」「複製」を書く。手札／デッキ／墓地に存在するカードを召喚する効果は、そのゾーンを書く。
- 生成、復活、孵化の処理経路は同一とは限らない。召喚時効果などの有無は実際の経路を確認する。
- カード名を引用する場合は最終的な各言語の表示名を使う。系統を指すなら「系」を付け、同名だけを指す表記と分ける。

## 数値・体力・コスト・カウンター

- 数値は原則アラビア数字。省略で比較条件を消さない。「以上／以下」は境界を含み、「未満／超」は含まない。
- プレイヤー体力に旧最大体力の概念を持ち込まない。回復、ダメージ、体力を直接指定値にする効果を区別する。
- モンスターの判定は **現在体力**、**最大体力**、**印刷体力**を区別。攻撃力＋体力の自動選択も、実装がどの体力を参照するか確認する。
- `体力±N（持続）` はモンスターの体力補正で、蓄積ダメージは取り除かない。最大体力は最低1。体力を指定値にする処理では蓄積ダメージを取り除くか明記。
- 能力値を `+3/+3` だけにしない。「攻撃力+3・体力+3」と主体を示す。生成するトークンの補足の `3/2` は攻撃力／体力の順。
- 購入コストと発動・召喚コストを区別する。割引の最低値、無料化が購入と使用のどちらかを書く。
- 一般カウンターの名称は `カウンター / 카운터 / counter`。**烙印カウンター / 낙인 카운터 / Brand counter** は別の概念。
- 名称を統一しても、異なる用途のカウンターが互換になるわけではない。参照・除去する用途を必要に応じて括弧で補う（例：気合に使うカウンター）。付与先、個数、消費の有無を明記する。
- 卵の **孵化までの残りターン** と **攻撃・ダメージで失うカウンター** を混同しない。

## 表示と検証

詳細画面は効果全文、キーワード名、ダイス表、関連する用語の説明を表示する。デッキ構成・リフト・持続・即効魔法・クエストの共通説明は `cardEffectNotes.ts` で三言語を管理する。文中の能力名は読める文字で残す。カード表面の小さなアイコンだけに説明を任せない。

`npm run text:check` は全ID／三言語の欠落、旧名称、言語混在、タグ・主要数値・結果表の言語間一致、監査後の文面／カード定義変更を検査する。選択・処理順・期限の正しさは実装照合と代表的な挙動テストで確認する。機械チェックの成功だけで「全ての意味が正しい」とは判断しない。

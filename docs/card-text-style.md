# カード効果の表記ルール

2026-10-08 改定。日本語・韓国語・英語の全カード、生成専用カード、スターター、キーワード説明に適用する。ゲーム処理やバランスはこの改定で変更しない。

## 三つの合格条件

**可読性**：必要な項目を探せること。**理解のしやすさ**：一度読んで具体的な行動に置き換えられること。**解釈の余地のなさ**：同じ状況から複数の結論が出ないこと。この三つを別々に評価する。短さだけ、厳密さだけでは合格にしない。

文字数上限は設けない。重要な条件を省略しない。長くなる場合は構造を変え、文字を縮小しない。短いカードに不要な説明を足すこともしない。

## 1. 一つの見出しに、一つの条件の範囲

基本形は `【タイミング】条件。対象・選び方・処理。期限。`。

- **購入条件・召喚条件・発動条件・攻撃条件**は、それを行えるかの制約。効果の途中の「～なら」と区別し、専用の段落にする。条件の段落に実際の効果を続けない。
- **異なるタイミングの効果は必ず別段落**にする。同じカードの召喚時効果と攻撃時効果を同じ段落に置かない。
- **同じタイミングで順に行う処理は同じ段落**に置く。句点で区切る。独立した効果と誤解させる空行や番号だけで分割しない。
- **一つの条件が複数の処理にかかる場合**は「～なら、次の全てを行う。」と明示するか、条件付きの一文として完結させる。後続の処理が無条件に見える書き方をしない。
- 見出しには既定の名称を使う。対応表は `client/src/shared/cardEffectHeadings.ts`。三言語で同じ順序・同じ範囲にする。新見出しは三言語同時に追加する。
- ` · `、スラッシュ、読点の連続だけで処理の関係を表さない。空行は正本に明記し、実行時に文章を解析して見出しや条件を推測しない。

| 改善前 | 改善後 |
|---|---|
| 発動条件：墓地にカードがある・1枚除外・1枚ドロー、烙印除去 | **発動条件**：自分の墓地にカードがある。 **発動時**：自分の烙印カウンターを全て取り除く。自分の墓地からカードを1枚まで選び、自分のリフトへ送る。送った場合、カードを1枚引く。 |
| ワイン2枚があれば除外して闇商人を得る。その後自身も除外 | 手札にワインが2枚以上あれば、**次の全てを行う**。2枚を自分のリフトへ送る。新しい闇商人を自分の手札に加える。このモンスターも自分のリフトへ送る。 |

## 2. 接続語は処理の仕様として扱う

| 表現 | 意味・使用条件 | 韓国語／英語 |
|---|---|---|
| その後 | 処理の順番。前の処理の成功を条件にしない。 | 그 후 / Then |
| ～した場合 | 指定の出来事が実際に成立した時だけ、後の処理を行う。 | ～했다면 / If you do, If destroyed |
| ～してよい。そうした場合～ | 前半は任意。行わなければ後半も行わない。 | ～할 수 있다. 그렇게 했다면 / You may … . If you do … |
| ～なら、次の全てを行う | 条件が成立した時だけ、列挙した全処理を上から行う。 | ～이면 다음을 모두 처리한다 / If …, do all of the following |
| 代わりに | 元の処理を行わず、置換後だけ行う。 | 대신 / Instead |
| さらに | 元の処理に加えて行う。 | 추가로 / In addition |
| いずれか一つ | 選択肢から一つだけ行う。両方は行わない。 | 하나를 선택 / Choose one |

「そして」「成功時」「発動後」だけで依存関係を済ませない。「成功」は何の成立かを書く。選択しただけでよいのか、実際の移動・破壊が必要なのかを確認する。破壊不能・選択取消・対象不在・場の上限の経路も読む。

この表は**文の意味**を定める。エンジンの実行順や中断条件を変更するものではない。ゲーム終了で処理が止まる場合や個別処理に例外がある場合、無条件に「残りは必ず処理される」と宣言しない。

## 3. 主体・対象・選択を省略しない

- プレイヤーは「自分」「相手」、モンスターは「このモンスター」「自分の場のモンスター」と書く。体力・マナ・シールド・雫・カウンターの受け手を特定する。
- 場の全体効果は**片側／両側、モンスター／永続魔法／クエスト**を明示する。「全カード」が本当に全種別を含むか確認する。
- プレイヤーの指定は「選ぶ」。自動選択は「自動で」と選択基準・同値の優先順。ランダムは候補を列挙し、複数回なら毎回選び直すかを書く。
- 必須の `N枚` と任意の `N枚まで` を使い分ける。取消可能なら「まで」「してよい」。不足時は取れる分だけか、処理が不成立かを実装で確認する。
- 「異なる個体」は同名でもよい。「N種類」は異なるカード名の数。「この個体以外」「同名以外」を混同しない。自身を数えるか重要な場合は明記する。
- 「そのカード」「これら」は直前の対象が一意な場合だけ使う。対象が切り替わる場合は名詞を繰り返す。
- 自動・ランダム選択にオーラ等の除外条件がある場合は個別に明記する。通常の選択制限を、異なる実行経路へ推測で適用しない。

## 4. タイミング・持続・回数を別々に決める

| 用語 | 用途 |
|---|---|
| 場にいる間／場にある間 | 発生源が場にあり、条件が有効な間の継続的な補正・制約。場を離れるとその補正はなくなる。 |
| ～した時／～するたび | 出来事に反応して行う処理。本文で主体と反復条件を特定する。 |
| 持続 | 対象モンスターが場を離れるまで残る付与・能力値の変更。付与元が場を離れても残る。 |
| このターン終了まで | 現在のターンだけ。後から出る対象も含むか必要に応じて明記する。 |
| 期間 | 効果の終了時点。発動後に数えることと、誰のターンを数えるかを書く。 |
| 回数制限 | 同名合計／各個体と、ゲーム中／自分の各ターン／場にいる間を組にして書く。 |

**効果見出しとして「常時」「永続」を使わない。** 「永続魔法」はカード種別として維持するが、期間無制限とは限らない。出来事に反応する処理を「常時」とひとまとめにしない。

「毎ターン」「Nターン後」「1回のみ」だけでは不十分。自分／相手／双方、開始／終了、発動ターンを数えるかを特定する。双方通算の期限を、自分のターン回数に置き換えない。発生源が消えても残る予約効果にはその旨を書く。

## 5. 数値・用語・ゾーン

- 数値はアラビア数字。「以上／以下」は境界を含む。「未満／超」は含まない。英語の `5+`、`cost 3-` 等の条件略記は避ける。
- 能力値は「攻撃力+3・体力+3」のように名前付きで記載する。対象が明確な能力値補正は数式表記を許す。生成モンスターの `3/2` は攻撃力／体力と説明できる場合に限る。
- モンスターの**現在体力・最大体力・印刷体力**を区別する。体力補正では蓄積ダメージは取り除かず、最大体力は最低1。体力を指定値にする処理は、蓄積ダメージの扱いも確認する。
- プレイヤーの回復・体力獲得・ダメージ・直接指定値への変更は実処理に合わせる。旧最大体力を持ち込まない。
- 購入・発動・召喚コストを区別する。割引の条件は効果本文の末尾へ埋めず、コスト項目に置く。最低値を記載する。
- 一般カウンターの名称は **カウンター / 카운터 / counter**。烙印だけは **烙印カウンター / 낙인 카운터 / Brand counter**。名称統一で異なる用途が互換になるわけではない。
- カウンターの付与先・個数・増減・消費を示す。複数用途を誤認し得る場合は「気合用」「腐敗の処理」「提示更新用」等を添える。卵の耐久と孵化までの残りターンは**別見出し**にする。

| 用語 | 範囲 |
|---|---|
| 墓地 / 묘지 / graveyard | 捨てたカード等を置き、デッキ補充に使う場所。旧名称シェルフを使わない。 |
| リフト / 리프트 / Rift | 除外されたカードの場所。通常のデッキ補充には使わない。 |
| デッキ / 덱 / deck | 現在の山札だけ。 |
| デッキ構成 / 덱 구성 / deck composition | デッキ＋手札＋墓地＋場のモンスター。場の魔法・クエストとリフトを除く。 |

移動元・移動先・所有者を明記する。既存カードの移動と、新しいカードの生成・複製を区別する。引用名は最終カード名に合わせる。特定の同名カードと「～系」を区別する。生成・復活・孵化で召喚時効果の扱いが同じとは限らない。

## 6. 三言語で同じ判断ができること

逐語訳より自然な文を優先する。ただし条件・対象・選び方・数量・処理順・依存・期限・回数・ゾーンは変えない。日本語だけに補足しない。説明を短縮するための他言語フォールバックや英語だけの略記を禁止する。

各カードについて三言語で次に答える。答えが異なる、または本文と必要な共通用語から答えられない場合は再編集する。

1. いつ使える／いつ起きるか。何が条件か。
2. 誰が何を、何個、どこからどこへ動かす／変更するか。
3. 選ぶのか、自動か、ランダムか。選ばず終えてよいか。
4. 前の処理を行わなかった／できなかった時、後の処理は起きるか。
5. いつまで続き、何回起きるか。自身・同名・後から出るカードを含むか。

## 7. 表示と検証

正本は `client/src/shared/cardEffectText.ts`。三言語を同時に編集し、最終カード定義へそのまま適用する。新カードの欠落はエラーとする。専用ID分岐や `CUSTOM_SPELLS` は一般の `act` / `val` より優先して確認する。

詳細画面は見出しと本文、名前付きキーワード、ダイス結果表を表示する。必須条件・選択肢・例外・回数は本文に残す。用語・共通ルールは開閉可能な補助欄とする。本文は三言語・狭い画面でも省略せず、横スクロールや文字の極端な縮小で収めない。

ダイスの表は ` — ` の後を ` / ` で区切る。各行は `1-2: 効果`。共通条件は表の前に記載する。条件付きの別結果は、最後の行だけにかかる位置へ置かない。

変更後は全ID・三言語・非テキスト定義の不変性を監査する。`npm run text:check` は欠落・旧用語・数値集合・見出し順・結果表・レビュー後の変更を検出する。**この検査は意味の同一性や人の理解度を証明しない。** 意味は実装照合、読み取り設問、分岐の挙動テストで確認する。表示は実際の描画関数の全件検証とブラウザーで確認する。

## 8. 自己評価の基準

各軸を5項目×20点で別々に採点する。95点以上を目標とし、重大な意味の欠落が一つでもあれば点数に関係なく不合格とする。

| 軸 | 20点ずつの確認項目 |
|---|---|
| 可読性 | 見出しから探せる／条件と処理が分離／一文が追える／本文と補助情報が分離／三言語・狭い表示で全文が読める |
| 理解のしやすさ | 主体が明確／行動に置き換えられる／用語が一貫／具体的な分岐を説明できる／他カードに同じ規則を適用できる |
| 解釈の余地のなさ | 条件範囲／対象と選び方／順序と依存／期間と回数／数値・ゾーンが実装と一致 |

自己評価は編集者の判断として報告する。機械検査の成功を95点の根拠に置き換えない。初見プレイヤーや母語話者による読み取り検証をしていない場合、それを実施済みと扱わない。

監査台帳：`docs/card-text-audit-2026-10-08.json`。読み取り確認：`docs/card-text-comprehension-2026-10-08.md`。前版の監査記録は履歴として保持する。


## 9. カード効果を理解するためのUI契約（2026-10-08追補）

- 全カード名は各言語内で一意にする。異なる効果を同じカード名で識別させない。名称変更時もゲーム内部のIDと効果は維持する。
- 本文で使うパッシブは、そのカードが持っていなくても詳細画面内に説明を用意する。見出しは「このカードが持つ能力」「この効果で付与する能力」「効果文に出てくる能力」と役割を明記する。付与する能力と、それ以外の対象条件・無効化などで触れる能力を混ぜない。名前とアイコンの両方から説明へ移動できるようにする。魔法が付与する能力を、魔法自身の能力として表示しない。「効果中の用語」のように、何を指すか読み手が推測する必要のある見出しは使わない。
- 実際に付与された能力も説明リンクの対象にする。条件付き能力は条件成立中であることを表示する。付与能力と状態を同じアイコンの説明へ押し込まない。
- 腐敗を与える能力と、腐敗を受けた状態を分ける。状態には用途・現在数・閾値・閾値到達時の処理を示す。「カウンター」の統一名称を維持し、用途ラベルで区別する。
- 盤面から詳細を開いた時は、現在体力／最大体力、用途別のカウンター、付与能力、補正と終了時点を表示する。詳細を開くことで盤面の情報が欠落してはならない。カタログには未発生の現在値を表示しない。
- 三言語の補助説明は `cardRuleMetadata.ts` の意味情報を共有する。翻訳文の括弧・単語の綴りから実行時に説明の必要性を推測しない。新しい用語・付与能力・効果を追加したら、この情報も同時に更新する。
- 種別名、アイコンの補足、クエスト進捗、検索を本文と同じ監査対象にする。クイック魔法は「リフトに置いてから効果を処理する」で統一する。墓地の旧名称を再導入しない。
- 全言語でカード名・効果本文・参照パッシブを検索できること。能力を持つカードと付与するカードを絞り分けられること。
- 説明へ移動したら本文の元の位置へ戻れること。関連カードからは元のカードと閲覧位置へ戻れること。キーボードの操作位置も復元する。スマートフォンでは閉じる操作を常に表示する。
- 合格条件は全文表示に加えて、用語参照の網羅、状態と能力の区別、名称の一意性、三言語の補助説明の一致、検索、往復操作を含む。自動検査と初見プレイヤーの理解度検証は別に報告する。


## 10. 文字の可読性と視認性（2026-10-09追補）

- 詳細の本文はPCで18px、850px以下で17pxを標準とする。長文・三言語でも縮小せず、段落と縦スクロールで読む。実装はremを用いて利用者の文字拡大に追従する。
- パッシブ説明、共通ルール、現在状態、種族条件・ボーナス、確率表は16px以上。意味を理解するために読む文を補助情報として薄く・小さくしない。本文・説明・表の行高は1.75を基準とする。
- 発動条件・パッシブ名は16px、太字。グループ名・種別・戻る操作など短い補助ラベルは14px以上。意味の階層は大きさ・太さ・間隔で示す。
- カード名は世界観に沿う書体を維持し、効果・説明・条件は各言語のUI用ゴシック体を使う。韓国語の説明文は語のまとまりを維持し、狭い幅ではあふれる語だけを折り返す。
- 通常・ホバー・移動先の強調・キーボードフォーカスをそれぞれ確認する。通常文字は背景とのコントラスト4.5:1以上。パッシブ名は濃い青の説明面と強調背景の両方で7:1以上を目標とする。文字や説明欄のopacityで階層を付けない。
- 320px・390px・PC・横向き、200%文字拡大、利用者による行間／字間変更で、全文・閉じる操作・本文への復帰を保つ。文字を大きくした結果の欠落・横はみ出し・見出しへの隠れを検査する。スマートフォンで固定するのは操作ボタンの行だけとし、長いカード名は省略せずスクロールできるようにする。
- 上記はLOREの表示基準であり、全利用者に対する可読性やWCAG全項目への適合を保証するものではない。自動計測、ブラウザー目視、実機・初見プレイヤー評価の範囲を区別する。

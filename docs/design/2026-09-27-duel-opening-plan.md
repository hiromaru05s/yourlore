# LORE デュエル開幕演出プラン

2026-09-27。提案・設計のみ。ゲームコード、素材、本番・ステージングへの変更は含まない。

## 結論

推奨は「シーカーの対峙から、同じ盤面へ入る」5.8秒のシークエンス。キャラクターを見せる前半と、コイン・カードの質感を見せる後半を一本の流れにする。

目指す品質は、構図、予備動作、短いピーク、接地、音、操作への引き渡しが揃っていること。静止画の拡大縮小だけでは最終品質に届かない。専用のキャラクター短尺素材と、質感のある効果音を制作工程に含める。

名称は制作上の案名。新しい世界設定やゲーム内用語の追加ではない。正典のビブリオン、シーカー、デュエル、赤／青の人物を使用する。

## 確認した現状と限界

調査対象は Desktop/LORE_TCG、HEAD 8b37408。作業中のホーム等の変更があるため触れていない。画面は保存済みの `docs/ui-rework/2026-09-21-reading-board/ingame-1920x1080.png` を確認。現在公開中の開幕を実再生して評価したものではない。

- `client/src/game/controller.ts:524` の `afterApply()` は `syncTimer()` の後に開幕へ進む。
- `showCoinToss()` は完成済み盤面にオーバーレイを追加。コイン、先攻表示、ターン告知、両者の初期3枚の配札へ進む。複数の `setTimeout` で制御している。
- `client/src/ui/coinScene.ts` は専用カメラとレンダラーを使用。メッシュには厚みと縁があるが、実盤面とは別の空間。回転は約2.2秒で、結果音は呼び出し側の1.7秒、文字はCSSの1.8秒基準に分かれている。
- `duelScene.ts`、`boardProjection.ts` には盤面とカードの共通投影がある。`BOARD_TILT` は固定。カメラだけ動かすとDOMと3Dがずれるため、真のカメラ移動は単純な追加ではない。
- `duelReadiness.ts` には画像、GLB、シーンの事前準備がある。
- 現チェックアウトの `sound.ts` はサンプルと合成音の混在。`coin` は合成音。別ブランチの36クリップを現行実装済みとは扱わない。
- `server/src/gameRoom.ts` はサーバーの `turnStartAt` を基準に時計を管理。ランクのマーケット確認終了時に時計を開始し、開幕演出はクライアント側で進む。
- 過去の dd855a4 には `duelOpening.ts` / `ceremonyScene.ts` があることをgitオブジェクトで確認。現チェックアウトには含まれない。過去worktreeはprunable表示。全体を取り込まず、再利用候補の音声管理・キャンセル処理を個別に評価する。

構成上の課題という仮説: 対戦相手の登場、コイン、配札が別々のUIとして見え、観客の視線と音のピークが一本につながりにくい。実装に入る最初の段階で現行の録画を撮り、この仮説を照合する。

## 3つの演出案

| 案 | 一番見せたい瞬間 | 表現 | 制作負荷・弱点 |
| --- | --- | --- | --- |
| A. シーカーの対峙 | 大きく見えた二人が盤面の肖像へ収まる | 左手前の青、右奥の赤。短い所作と視線。人物から卓上へ連続して移行 | 推奨。人物の良い短尺素材が必要。低解像度の肖像拡大では成立しない |
| B. 卓上の起動 | コインの金属音と、カードが手元へ届く感触 | 盤面の金属縁に光が走り、アチューンが一度呼応。実卓上でコイントス | 既存3Dを活かせる。人物への愛着と対戦相手の存在感はAより弱い |
| C. 記録の具現化 | 一枚のカードから一瞬だけ記録が立ち上がる | 中立のビブリオン意匠を起点に、紙の輪郭が空間へ展開し盤面を見せる | LOREらしいが専用VFXの負荷が高い。未公開デッキ情報を使わず、追加設定も作らない |

推奨はAを主軸にBの接地感を採用。Cは特別イベント等の後続候補。毎試合は演出を短く保つ。大きなVS、ロゴ、先攻、ターン開始を順に何度も中央へ出す構成は避ける。

## 推奨案の絵コンテ — 通常版5.8秒

尺は初期提案値。素材完成後に調整する。マーケット確認とロード待ちはこの尺に含めない。

| 時間 | 画面と視線 | 動き | 音 |
| --- | --- | --- | --- |
| 0.00–0.35 | 同じ盤面が薄暗く見えている | 環境の明るさを抑え、人物に視線を集める。完全な黒画面を挟まない | 短い吸い込み、低い空間音 |
| 0.35–1.65 | 青のシーカーが左手前、赤が右奥で対峙 | 肩・顔を十分大きく見せ、短い所作を一度。二人はわずかに時間差。名前は人物の近く | 布の擦れ、魔力の短い上昇音。ボイスは後続の任意要素 |
| 1.65–2.35 | 人物から盤面の肖像へ視線を導く | 拡大表示を実際の肖像位置へ移動・縮小。マスクを全身寄りから顔へ収束。盤面を露出させる | 上昇音を収め、軽い金属の収まり音 |
| 2.35–3.85 | 卓上の空きレーンにコイン | 予備動作→弾く→回る→一度強く接地→小さな揺れ→停止。接触影と狭い光の弧 | 弾き音、薄い回転音、接触時の金属＋卓の低音 |
| 3.85–4.45 | 先攻側の肖像へ | 確定したコイン面を読ませてから先攻の肖像が一度応答。短い先攻ラベル。コインは退場 | 先攻確定の短い和音。ここを唯一の強い決めにする |
| 4.45–5.50 | デッキから手元へ | 両者へ3枚ずつ。各カードを約100msずらし、最後の一枚で手札を整える。自分の表は所定のタイミングで開示 | 紙の厚みがある3拍、最後に小さく着地 |
| 5.50–5.80 | プレイ可能な盤面 | 先攻側の操作箇所へ明るさを戻す。既存ターン表示に繋ぐ。演出用物体を完全に撤去 | 小さな完了音。余韻を残して音量を下げる |

人物間の巨大なVSを主役にせず、「相手がこちらに向き合う」構図を主役にする。衣服や髪は大振りにしない。人形全体をふわふわ動かす代わりに、所作→静止の間を置く。

コインは盤面中央のマーケットを塞がない空きレーンを選び、モバイルでは空き領域に合わせて座標・大きさを再構成する。画面全体を白く飛ばさず、光を接地点と先攻肖像に限定する。

## 素材と表現方式

### キャラクター

- `docs/characters/2026-09-07-approved/{red-reader,blue-reader}.png` を外見の基準にする。
- 既存方針 `docs/character-concepts/2026-09-07-reference-red-blue/animation-playback.md` に従い、完成済み短尺の固定再生を採用。Live2D導入や新規フル3D人物は必須にしない。
- 各人物に登場用の静止キー画＋0.8〜1.2秒の一回再生クリップを1本。まず片方を制作し、顔・手・服の連続性を確認してから二人目へ展開。
- 仮素材の段階では既存絵の移動で尺を検証。本制作では短い身体の所作、髪・布の遅れを素材に焼き込む。画像生成で作った単一静止画を完成アニメーションと扱わない。
- 納品候補は透過WebPアトラス、フレーム時刻・基準位置を持つJSON、静止フォールバック。1コマ768×1024、12コマ程度を最初の実測候補とし、ページは端末の最大テクスチャ寸法内に分割する。12コマの非圧縮RGBAだけで約36MiB/人になるため、モバイルは384×512等に落とす。画面内の実寸とVRAMで最終決定。
- 顔、髪、指、衣装、アルファ縁の崩れをコマごとに修正。キャラクター名や台詞の新設定はこの演出に含めない。

### コインと光

- `createCoin()` の形状を再利用し、盤面シーンに取り付ける部品へ分離。独立したコイン用カメラを重ねる構成から、盤面と同じカメラ・照明・高さに揃える。
- 先攻はサーバーの確定結果を表示する。見た目の回転で再抽選しない。回転は決定論的なカーブとし、どちらの面も同じ停止時刻にする。
- 接触影はコインの高さ・姿勢に応じて変化。接地イベントを音・小さな揺れ・光の共通起点にする。
- VFXは `docs/vfx-art-direction.md` のToon基準。薄い輪郭の弧、白い芯、色面の欠けと分裂。参照のimpact 25.70秒付近を制作時に再確認する。粒数増加や一様なフェードだけにしない。
- 初回に必要なVFXは、接地の短い弧と先攻肖像への応答の2種類。顔やマーケットの可読性を優先する。

### 視点の移行

初版は固定の盤面カメラを維持し、前景人物の縮小・移動、マスク、盤面照明の復帰で「卓に入る」感覚を作る。これで現在のDOMと3Dの投影を壊さずに制作できる。

本物のカメラの引き・傾斜変化が必要と判断した場合のみ第二段階で共有のレンズ状態を導入し、`boardLens`、`boardMatrix`、`screenToBoard`、`duelScene` のカメラを同時更新。カードと3Dが1フレームでもずれるなら固定カメラ版に戻す。カメラ移動ができたことを品質の基準にはしない。

### 音

効果音6系統（導入、布／魔力、コイン弾き、コイン接地、先攻確定、配札）を用意する。金属・紙・布は収録または利用条件を確認した素材を編集し、合成音は魔力の層に使う。配札は小さいバリエーションを用意する。素材の入手先と利用条件をmanifestに残す。

実装は既存の音量・ミュート・ジェスチャー解除に接続。接地の瞬間と音を共通時刻で指定し、別々のタイマーにしない。開幕用の音声グループを用意し、スキップ・退出時に停止または短いフェードで終了。ボイス無しでも成立する構成を先に完成させる。

## 実装構成

以下は新規・変更予定で、現行APIとして存在するという意味ではない。

| 対象 | 担当すること |
| --- | --- |
| 新規 `ui/duelOpeningDirector.ts` | 一つの時刻と状態機械で全演出を進める。通常終了、seek、短縮、キャンセルを共通化 |
| 新規 `ui/duelOpeningTimeline.ts` | 通常／短縮版のキーフレーム、接地・確定・配札のキューをデータ化 |
| 新規 `ui/seekerOpeningClip.ts` | アトラス再生、静止フォールバック、最終肖像との同位置引き渡し |
| `ui/coinScene.ts`、`ui/duelScene.ts` | コイン部品を盤面シーンに接続。所有権・disposeの境界を明確にする |
| `ui/boardProjection.ts` | 実際の盤面と肖像のアンカーを取得。真のカメラ移動は後続段階 |
| `ui/anim.ts`、`ui/paperDraw.ts` | 既存配札を再利用し、director側から完了・中断を待てる形にする |
| `ui/duelReadiness.ts` | 必須と任意素材を分離。ロード失敗・時間切れ時に軽量版へ移行 |
| `ui/sound.ts` | 開幕キューの予約、停止、既存音量との統合 |
| `game/controller.ts` | `showCoinToss` の分散タイマーを置き換え、演出中の入力と状態更新を分離 |
| `dev/duelLab.ts` | 開幕の再生・任意時刻停止・先攻切替・軽量版・エラー再現を追加 |
| `server/src/gameRoom.ts` と通信型 | 対戦開始時刻の共有と開幕フェーズ。サーバー基準の入力受付と時計開始 |

状態機械: `preload → faceoff → dock → toss → reveal → deal → ready`。全状態から `abort` / `fastForward` 可能。一つのAbortControllerが人物、3D、音、配札を止め、finallyでoverlay、入力ロック、非表示の手札を復旧する。

表示中もサーバー更新は受け取る。古い初期状態へ巻き戻さない。再接続、観戦途中参加、既に進行中の第1ターンではフル開幕を再生しない。相手の手札は枚数・裏面のみ使い、未公開のカードIDや乱数を演出データに含めない。

## 時計・待ち・スキップ

開幕を長くする前に解決する必須項目。現状のクライアント時計を止めるだけでは、オンラインのサーバー時計は止まらない。

- ランクの既存マーケット確認は維持。その後にサーバー管理のopeningフェーズを置く。通常対戦も同じ開始経路に揃える。
- 必須準備完了を両者から受けた後、サーバーが共通の `openingStartAt` / `playableAt` を確定して通知する案。終了通知を待って無期限停止する方式にはしない。
- 準備待ちは期限付き。任意素材が間に合わない端末は軽量版で参加。通信未成立の待ち・切断判定は既存方針に従う。期限の具体値はネットワーク試験後に決める。
- `playableAt` 以前のゲーム操作はサーバーで拒否。時計はその時刻を基準に開始する。クライアントは権威時刻との差を使い、低fps・背景復帰で演出が遅れても現時刻へseekする。
- スキップした側には盤面を先に見せるが、両者の操作開始は同じ `playableAt`。ローカルの演出設定で先攻の持ち時間や操作権を変えない。両者合意で開始を早める機能は初版に含めない。
- BOTはローカルのready時刻から時計とBOT行動を開始。観戦・再接続は現在状態を直ちに表示する。
- Durable Objectの開始時刻・フェーズは永続化。既存のjoin/forfeit/preview/turnをまとめる `syncAlarm()` に組み込み、開幕専用alarmで他期限を上書きしない。重複ready、再起動、再接続でも開始を一度だけ決定する。
- 旧クライアント・既存ルームとの互換性を試験し、サーバー／クライアントを対応するバージョンで段階展開する。

演出尺の候補: 通常5.8秒、短縮2.4秒、reduce-motionは静止の両者紹介と先攻表示。短縮版も音を単純倍速にせず再配置する。これらは表示差でありオンラインの開始時刻差にはしない。

## 制作順と各段階の完成条件

1. **現状録画とアニマティック**: 現行開幕を実再生し、推奨案5.8秒を既存の絵・簡単な形・仮音でduel-labに組む。現行と比較できる録画、0.25倍速、任意時刻停止を用意。構図とテンポをここで判断する。
2. **最難所の2秒を完成**: 人物が肖像へ収まる遷移と、卓上コインの接地を実画面で仕上げる。接地影と音が揃い、重複肖像やテレポートがないことを確認する。ここが弱いまま粒子を足さない。
3. **専用素材・音の制作**: まず人物一人を完成。承認原画との整合、アルファ、低解像度版を確認してもう一人へ。VFX2種、音6系統を制作し、manifestに寸法・尺・hash・出所を保存する。
4. **フル演出とゲームへの接続**: director、配札、準備、キャンセル、通常／短縮／静止版を接続。既存のゲームルールと初期手札を維持する。
5. **オンライン同期**: openingフェーズと共通開始時刻を実装。二つのクライアントでネットワーク遅延・片側スキップ・再接続を再現し、時計と入力受付を検証する。
6. **仕上げと出荷判断**: 実機の録画・代表フレーム・パフォーマンスと機能試験結果を保存。ローカル試作、統合、ステージング、認証付きオンライン、本番を別々に報告する。

## 検証・品質基準

- 開幕だけで「誰と対戦するか」「どちらが先攻か」「もう操作できるか」が分かる。
- 人物の登場→肖像、コイン→先攻表示、カード→実手札が同じ座標と所有権で繋がる。切替フレームで二重表示や消失がない。
- 通常速度で最も強い決めが一つ。停止フレームで顔・コイン面・光の形が読める。灰色の幕で盤面全体が長時間汚れて見えない。
- 1280×720、1920×1080、スマホ縦横、長いユーザー名、日本語／英語／韓国語で画面外へのはみ出しを確認する。
- 先攻／後攻、初回コールドロード、キャッシュ済み、WebGL不可、音声未解除、素材失敗、reduce-motion、退出、降参、resize、背景復帰、連続再戦を確認する。
- 途中のどの時刻でキャンセルしても、音・RAF・overlayが残らず、実手札と操作ロックが正常に戻る。
- 相手手札情報を使わない。フレーム落ちや再接続で配札を二度実行しない。
- デスクトップ60fps、モバイル30fpsを最初の目標に置く。実測でフレーム時間・長い停止・GPU資源を確認する。未達なら人物解像度、影、補助VFXから段階的に落とし、動きの順番と先攻の可読性を維持する。
- テストは新directorの時刻・中断・重複開始、実controllerの配札／バナー／入力、二者接続の開始時刻／再接続を重点化。既存 `tests/duel-ui.mjs` 等は現行実装との整合を確認してから拡張する。古い家具登場を期待するテスト結果を新開幕の証拠に流用しない。

## 見積もりと判断

固定カメラ＋人物の短尺再生＋共有卓上コインは、現在のブラウザー実装を活かせる現実的な構成。品質上の最大の不確実性は、人物の短尺素材と音の仕上がり。真のカメラ移動、二人のフル3D、リップシンク、長い台詞、巨大な図書館移動は初版の必須にしない。

工数は、既存素材での実画面アニマティックを作った段階で再見積もりする。今回の絵コンテを完成演出・実装済み・AAA品質達成として扱わない。

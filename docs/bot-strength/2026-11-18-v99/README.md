# v99 Bot難易度の更新・検証

カードの数値・効果はv99のまま。Botの判断、探索量、スターター構成を更新した。

## 配信する仕様

|難易度|スターター|判断|
|---|---|---|
|かんたん|ハーフエルフ、ゴブリン、ファイアー、カル3、宝箱2|通常の行動選択で12%の確率で別の合法手を選ぶ。必須の対象選択は崩さず、意図的な手番放棄・即敗北を候補にしない。別候補がなければ通常手を使う。|
|ふつう|精霊コントロール、吸血鬼、ゴブリン、精霊マナ成長の4構成|候補と未知情報サンプルを増やし、有力候補を相手の応手まで再比較。仮想的な行動処理は最大3,500回。|
|むずかしい|精霊防御、精霊＋ゴブリンの2構成|確定勝ち筋の探索、広い候補比較、相手の応手、その後の展開まで評価。仮想的な行動処理は最大14,000回。|

初期体力・マナ・既存のマーケット優遇率は変更していない。内部のHellも上位ロジック・デッキ集合を共有するが、Single画面で選べる難易度は3段階。ストーリー固有の初期デッキは変更していない。

主な判断修正:

- 傭兵の購入価格と購入直後の雇用費を区別。エンジンと同じ召喚制限を確認し、雇用に必要なマナをリロールで使い切らない。
- ミニ精霊を出してから基本アチューンを使う順序を認識。
- ゴーレムの気合を消費して使えない精神放出術を増やす動きを抑制。得た精神放出術を勝ち筋・十分な打点として使う。
- 傭兵術を現行の召喚・マナ獲得による強化として評価。
- 購入直後に効果があるカードも、その手番の確定勝ち筋探索に含める。未知のドロー、ダイス、相手の伏せ札を勝利の証明に使わない。
- 商人によるマーケットだけの入れ替え、選択待ちキューの消費も有効な進行として扱う。
- 重い局面では計算量の上限で終了し、候補を同条件で比較し終えた直近の手を採用。相手の非公開情報を直接使わない観測モデルを維持。

探索上限は計算量であり、実対戦数ではない。有限かつ不完全情報下の探索なので、すべての局面の数学的な最適手を保証するものではない。

## 構成を絞った理由

高速な代理評価では強かった構成も、実際の探索を使うと成績が変わった。候補7構成の対ふつうは56戦36勝。精霊防御・精霊成長・精霊＋ゴブリンの3構成は24戦20勝だったため、まずこの3構成を別シードで検証した。腐敗混成も6勝／8戦で一部候補と同率であり、小標本で厳密な順位を確定したわけではない（`selection.json`）。

その後、旧Bot比較が完走し、精霊成長型が旧ゴブリン・旧腐敗混成の速攻2構成に4戦全敗と判明した。むずかしいの構成ごとの弱点を減らすため、配信対象を精霊防御・精霊＋ゴブリンの2構成へ絞った。この最終選抜に使用した成績と、選抜後の独立試験を混ぜていない。

## 試験の区別

|段階|内容|実施試合数|
|---|---|---:|
|高速なデッキ選抜|24候補を簡易方策`greedyStep`で比較した最終確認|5,760|
|候補7構成の実思考比較|対ふつう56、対旧むずかしい28、ふつう対かんたん48|132|
|候補3構成の独立確認|むずかしい対ふつう48、ふつう対かんたん48|96|
|配信2構成の独立確認|むずかしい対ふつう16、むずかしい対旧速攻2構成8|24|
|基本デッキからのかんたん確認|カル6・宝箱2を公開情報の簡易方策で動かす|200|

実思考比較252戦は`botDecide`と実エンジン、実際の初手交換を使用し、同一シードで先後を入れ替える。マーケット優遇は両側とも無効にし、判断とデッキの組み合わせを測る。人間の勝率でも、AI単体の寄与を分離した実験でもない。

かんたん確認では基本デッキ側が200戦130勝（65%、シードペアのブートストラップ95%区間58–72%）。これは人間の初心者の勝率ではない。

初期の追加評価でマーケット選択の進行判定が1件停止したため修正した。失敗したシード381061も再実行し、22ターン・97アクションで完走を確認した（`market-regression.json`）。最終の代理評価5,760戦は全件完走。不完全な予備実験や中断した試行は実思考集計に含めない。

## 再現性・解釈の限界

`provenance.json`に元コミット・各評価スナップショットのSHA-256・ソースのSHA-256を保存した。旧Botは元コミット`9e99fbfd51a85a50cd025840edd333a9c892276d`のGit archiveから再ビルドし、保存済み旧スナップショットとの一致を確認済み。

`baseline.cjs.gz`は旧Bot、`candidate.cjs.gz`は候補7構成、`final-candidate.cjs.gz`は候補3構成、`release-candidate.cjs.gz`は計算関数整理の統合後、`shipped-candidate.cjs.gz`は配信2構成の固定実装。`final-jobs.json`、`release-jobs.json`、`shipping-jobs.json`が対戦条件。各対戦の生データは圧縮JSONに保存する。`ml/bot-strength/v99-report.cjs`は完走数・無効試合・コードの一致を検査して集計する。

最新main `4c94f2501` の軽量化を統合した。計算関数を`cardStats.ts`へ移動した変更は、17個の関数・初期化式と残る282宣言をASTで照合し、1,200状態遷移・24判断も一致した（`integration-parity.json`）。配信2構成の独立試験はこの統合後のコードで実行する。

区間推定は先後をまとめたシードペアを単位にする。全勝・全敗ではブートストラップ区間が見かけ上0幅になるため、`scoreInterval95`には独立なペア得点を仮定した保守的な境界区間を使う。小標本の対旧速攻8戦を、全デッキに対する優位の証明とは扱わない。

実思考比較は手番時計・描画を省いたヘッドレス実行。オンラインNPCには、残り45秒未満ではふつう相当の探索へ切り替える既存制御があり、ブラウザーにも15秒の思考ガードがある。重い局面では途中まで比較できた手を使うため、オフライン成績は端末・時計を含む実プレイ勝率と同一ではない。計測時間も共有マシン上の観測値。

採用2構成はどちらもミニ精霊を軸にするため、成長を止める除去・攻撃力抑制との相性は残る。防御型同士では長期戦になり得る。60ターンの体力判定と通常決着は集計で分ける。

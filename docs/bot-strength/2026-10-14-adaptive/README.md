# v58 BOT: 状況に応じた購入と構築選別

目標は、対策構築を使う上級者に対してHardが約70%勝つこと、Hellがさらに強い7構築を使うこと。人間との試遊は未実施で、この目標の達成はまだ証明していない。カード数値・構築ルール・初期資源は変更しない。

## 実装

- 購入を単体評価だけで決めず、所有する支援、召喚条件、マナ曲線、相手の公開済みカード、マーケットの支援札・在庫、重複、引くまでの遅さ、残りターンから限界価値を計算する。
- 初めて必要になる永続魔法対策は、既存デッキの高い平均点に阻まれない。相手の最大マナが7を超えた逆算は対策の所持枚数に数えない。一時除外から戻るカードと永久除外も区別する。
- 同じ状況評価を探索のBUY候補と将来局面の評価へ接続。更新費用を払った後に買えるカードから、提示更新の期待価値を計算する。実際の乱数や非公開の提示は見ない。
- 装置解除・装置分析・魔法研究機関を実際に使用する。全体弱体化・攻撃阻害の解除・裂け目の準備に必要なマナを、先行する小型召喚で使い切る判断を修正する。
- ポイズンマスターはHPだけで倒せるかを判定せず、腐敗カウンターによる撃破も含めて大きい脅威を狙う。世界樹の回復倍率を現行v58の非重複ルールに合わせる。
- 血鬼術・ブラックリバース・インフィニティを踏まえて確定火力の対象・回復・反射を評価。自傷は固定HPしきい値だけに頼らず、シールドや魔法増幅を含むエンジン結果から即死を避ける。亀裂の触媒も使用候補へ追加した。ダイスで妨害にも分岐する三撃の火種は、確定火力や相手を回復するだけの魔法として扱わない。
- 5／7構築を実際のNPC選択へ接続。直前と同じ構築を避ける再戦抽選と、各構築の合法性を確認する。Hard/Hellには意図的なランダムミスを追加しない。

## 選別方法

最初の7系統案（腐敗・速攻・賭博・裂け目・エルフ・城・吸血）は、弱い相手の混じる比較では良く見えたが、旧ヘル相手の336対局でエルフ0/48などの穴が出たため不採用にした。次の候補でも、独立シードで裂け目型が28/96となり、採用前に再選別した。

探索を2段階で計21,120試合行い、旧ヘル3構築、対策構築、新たに見つかった強構築を相手にした。構築を選ぶ前の再評価には別シードを使う。第2段階の再評価は24候補を予定したが、判断の追加修正に伴い、完了済み18候補×320試合＝5,760試合で区切った。残り候補の途中結果は採用にも勝率集計にも使わない。さらに最新方策同士の総当たりに、全体弱体化や逆算を増やした対腐敗構築を加え、固定数の構築を等確率で使ったときの最悪の対戦相性を優先する。

総当たりは16候補・1,920試合。初期構築に卵の生成手段を持たない孵化支援入り候補は採用対象から除外し、相手集には残した。採用構築は `selection.json` に固定し、その後の別シード検証では選び直さない。

現行版では腐敗を共通軸とする構築が強かった。採用数5／7は、全てが別の種族・別アーキタイプであるという意味ではない。弱い別系統を数合わせで採用しない。これは探索した対戦相手集に対する結果であり、全合法構築に対する最適性や人間への無敗を証明するものではない。

## 検証の読み方

- 簡易方策の大量対戦は、構築候補と基本方策の選別に使う。実際のHard/Hell探索や対人勝率と混同しない。
- 同じ構築で旧／新方策を比べる試験は、判断変更の影響を測る。構築も変更する製品全体の比較とは分ける。
- 先後・市場・相手・シードを記録し、完走・不正行動を全件確認する。引き分けは0.5点。改善しない結果も残す。
- 実探索の対戦は標本が小さいため、強さの保証ではなく統合・回帰確認として扱う。ブラウザではWorker上限、途中結果、停止・置換、画面応答、実Controllerの進行を別途確認する。
- `exploratory/` は撤回した構築と中間検証。そこにある当時の `final-candidate` も採用版ではない。

対人校正、以降の強化順序、採用の判定方法は [PLAN.md](PLAN.md) を参照。

## 自動対戦の結果

同一構築・同一シード・先後の旧新版比較は1,120試合（280組、40シード群）。簡易方策の勝ち点率は84.11%→86.43%、差+2.32ポイント。シード群で再標本化した差の95%区間は+0.18〜+4.46ポイント。改善21組・悪化8組・同点251組。不正行動・未完走は0。これはHard/Hellの実探索や人間との勝率ではない。

|市場|旧方策|新方策|
|---|---:|---:|
|自然|83.04%|82.14%|
|回復|86.61%|87.50%|
|永続魔法・除去|81.25%|86.61%|
|エルフ|82.14%|90.18%|
|呪い|87.50%|85.71%|

各市場のシード群は8個であり、小さな差を確定的な優劣と読まない。特に自然・呪い市場の悪化を隠さず、後続の実戦局面回帰の対象にする。中間の不採用ロスターでは同一構築の方策比較が-0.27ポイントだった記録も `exploratory/` に残している。

採用Hell7構築を旧Hell3構築と比較した672試合では588点、87.50%。両者とも簡易方策で、新側だけが新判断を使う。新構築別の点数は96試合ずつ、DECAY_BLOOD 91、DECAY_SUPPRESSION 85、BLOOD_RAIN 88、BLOOD_AMBUSH 85、SUPPRESSION_COUNTER 67、BLOOD_COUNTER 78、DECAY_SWARM 94。不正行動・未完走は0。

採用構築を固定した別シードの対策リーグは1,920試合を完走。両者とも新しい簡易方策を使い、16候補に対する均等配分の平均はHard5構築61.37%、Hell7構築58.15%、最悪相性はそれぞれ40.00%・38.39%。同一構築の対角は0.5として計算する。ここでのHard/Hellは構築集合の名前で、探索難易度の比較ではない。7構築へ広げることで苦手相性が増える事実を含む。新しい強構築を相手にした無敗は達成していない。

## 実探索・実行品質

実際の探索を使った製品比較48試合（同一相手・シード、両先後、旧新版）は全件完走、不正行動・打切り0。対戦相手は旧Hard方策で固定し、新旧それぞれの構築を使う。

|難易度|旧版|新版|差の95%区間|
|---|---:|---:|---:|
|Hard|5/10|5/10|-30.0〜+30.0ポイント|
|Hell|10/14|11/14|-21.4〜+35.7ポイント|

合計12組・7シード群。改善4組・悪化3組・同点5組。強さの改善を統計的に断定できる規模ではない。Hard70%・Hell無敗の達成確認には使わない。判断時間の最大は約4.94秒（Node上、同時試験を含む）。自然市場のみの実探索であり、固定市場の1,120試合とは試験条件が異なる。

- 新規28局面群に加え、既存の強さ・戦術・市場・シミュレーション・NPC・Worker・マッチBOT・v58クライアント／サーバーの計10テスト群が成功。
- NPCはEasy3／Normal3／Hard5／Hell7。構築の合法性、再戦での連続重複回避、コピー、36回の初動シミュレーションを確認。
- クライアント／サーバー型検査、製品ビルド成功。既存の大きな出力チャンクに関するビルド警告は残る。
- 最終共有main `7c999751` 取り込み後も、評価版との1,200局面の状態遷移・判断、11,988購入評価、40回のHard/Hell探索が一致。カード358種と構築・購入候補も比較元v58と同一。
- 最終版のブラウザWorkerで初期・複雑・戦術局面、時間上限、途中結果、キャンセル、置換、フォールバック、画面応答を確認。実ControllerではHard/Hell各2ターンを進行し、エラー0。認証付き対人試遊の証明ではない。
- 実対戦から採取した55ターン目の局面も、演出更新前の評価版のブラウザWorkerで約780ms、合法な進行・画面応答を確認。状態と結果を別ファイルで保存。

人間との勝率は未測定。完全無敗・全合法構築に対する最適性・全市場での改善は未達成／未確認。公開情報からの推定と短いロールアウトには限界があり、対人の敗因を再現局面へ戻す計画を `PLAN.md` に記載した。

## 再現

リポジトリの固定依存関係を `npm ci` で導入する。比較元は `baseline-v58.cjs.gz`、対戦集計を完全再現する評価版は `evaluated-v58.cjs.gz`（演出更新を取り込んだ最終版は `candidate-v58.cjs.gz`） を別の作業ディレクトリに展開し、それぞれ `before.cjs` と `candidate.cjs` とする。`selection.json` の `decks` を `selected.json` として同ディレクトリに保存する。`BOT_LAB` にそのディレクトリを指定する。出力先は毎回新しい名前にする。

- 構築選別: `selection-policy.cjs.gz` を使い、`league-adaptive-v58.cjs` に `exploratory/pool-holdout18.json.gz` の展開内容を入力。`SAMPLES=8`、`SEED_BASE=8310000`。採用条件は卵の生成手段のない孵化支援を除外する。
- 固定構築の別シード総当たり: `VALIDATE=1 SAMPLES=8 SEED_BASE=9410000` とし、保存された選別結果を入力。最終版の公開情報推定には新ロスターも含まれるため、評価用バンドルで再評価し、演出統合後は `check-adaptive-v58.cjs` で最終バンドルとの判断・状態の一致を確認する。
- 同一構築の方策比較: `SAMPLES=8 OFFSET=5100000` とし、`adaptive-v58.cjs paired`。自然・回復・永続魔法・エルフ・呪いの5市場、先後、旧新版の4対局を一組にする。
- 旧Hellの3構築との比較: `SAMPLES=16 OFFSET=5400000` とし、`adaptive-v58.cjs roster`。
- 実探索の製品比較: `SAMPLES=1 OFFSET=4000000 TIERS=hard,hell OPPONENT_TIER=hard MARKETS=natural SHIPPED_ROSTER=1` とし、`adaptive-v58.cjs product`。旧版は各難易度の旧3構築、新版は採用5／7構築。同じ相手・シードで先後と旧新版を比較。分割実行した結果は `merge-adaptive-v58.cjs` で重複・欠落・ハッシュを検査して統合する。
- `summarize-adaptive-v58.cjs` は4対局一組の完全性を検査し、シード単位の再標本化で差分区間を作る。市場・難易度・構築別も出力する。対人測定には使わない。

検証用スクリプトは `ml/bot-strength/`。バンドルのSHA-256とカード不変の確認は `integrity.json`。ブラウザの結果は `browser.json` と `gameplay-browser.json`。ローカル検証であり、ステージング・本番へは未配信。

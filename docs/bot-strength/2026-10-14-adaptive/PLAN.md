# v58 BOT強化計画

基準は gh/main の 3ce66bde（v58）。元の共有作業フォルダはv54系の未統合変更を含むため、専用worktreeで作業する。カード定義・ルール・初期資源を変更しない。作業中に進んだ gh/main の a876e26f（反逆罪の演出統合）をfast-forwardで取り込み、その後7c999751までの共有mainも取り込んだ。追加差分は演出イベント・UIで、カードはv58のまま。最終版と対戦評価版は1,200局面の状態遷移・判断、40探索、11,988購入評価で一致を確認する。比較用方策は3ce66bdeの固定バンドルを維持する。

## 目標と確認方法

- 難しい: 5構築、意図的ミスなし。対人70%は目標値。対策構築を使う上級者を対象に、参加者ごと・構築ごと・先後を記録して測定する。
- ヘル: 7構築、強い相手にも崩れにくい判断。完全無敗を約束せず、対策デッキ・未知の構築・実プレイヤーに残る負け筋を継続して潰す。
- 公開情報だけで対処する。非公開手札・順序・乱数、未公開の初期構築を見て有利な構築や行動を選ばない。

## 実装順

1. 現行v58方策を固定して比較用バンドルとカードハッシュを保存。
2. 購入を固定点数から限界価値へ: 自分の構築、召喚条件、相手の公開構築、利用可能なマーケット、重複、サイクル、発動までの時間を評価。評価理由をテスト・対戦解析で取得可能にする。
3. 同じ評価をBUY候補の絞り込みと将来手順に使用。既存のリーサル証明・相手による対象選択・途中結果保持を維持。実際の判断が変わる局面を回帰化。
4. 構築候補を広く比較する。7系統を揃えた初期案は旧ヘルに大敗したため不採用。強さを優先し、現行v58で強い腐敗を共通軸に持つ異なる配分・支援構成も候補へ含める。NPCの実際の抽選にも同じ5/7構築を接続。
5. 固定/自然マーケット、速攻・腐敗・回復・永続魔法・圧縮などの対策相手、先後・同一シードで旧版/新版を比較。探索用乱数と受入用乱数は分離。改善しない仮説は修正または不採用。
6. 型検査、カード不変、合法性・完走、非公開情報不変、Worker時間上限・実画面進行を確認。対人測定と公開状況は別に報告。

## 対人校正（実戦記録が必要）

参加者・難易度・NPC構築・人間構築・バランス版・先後・マーケット・勝敗・途中離脱・判断ログを保存。難しいの70%は同じ対象プレイヤー層で評価し、標本数と区間を併記する。少なくとも各構築で両先後を含む試遊から開始し、誤判断局面をテストへ還元する。ヘルは平均勝率だけでなく最も苦手な対策構築への成績を追う。自己対戦結果を対人勝率として代用しない。

## 対人校正の実施案

ユーザー指定の母集団は「対策構築を使う上級者」（2026-10-14回答）。Hardにも最上位5構築を採用する。Hardは5構築×40試合、Hellは7構築×40試合を初期目安に、先後を半数ずつ割り当てる。同じ人が複数回遊ぶため、試合を独立標本と決めつけず、参加者単位の区間・プレイヤー層別・各構築別を併記する。これは未実施の計画であり、募集・収集・外部送信を行ったという意味ではない。

Hardは70%へ合わせるために序盤からランダムなミスを混ぜず、思考予算や構築配分で調整する。Hellは勝てないと断定せず、上級者の対策構築や未知の市場に負けた原因を優先して回帰化する。毎回カードバランス版と方策バンドルを固定し、探索用・選別用・受入用シードを分離する。人間の敗北率は自己対戦の成績と混ぜない。

## 次に強くする順序

1. 実戦の弱い判断を再現状態へ落とし込む。BUYの内訳は `purchaseEvaluator` の base / synergy / matchup / readiness / redundancy / delay / denial / floor / margin で確認できる。
2. 相手のリーサル・回復・永続魔法エンジンに対する失敗を優先する。新しい重みは同一構築・市場・先後の旧新版比較で受け入れる。
3. 現在の固定対策相手に加え、人間の勝ち構築と過去の強い方策を対戦相手集へ追加する。単一の旧BOTだけを倒す最適化にしない。
4. 買ってから引くまで長いコンボは現在の短い読みでは不十分なことがある。個別コンボの長期評価を追加する際は、実時間上限・途中結果・画面応答を保ち、実探索で向上するか確認する。

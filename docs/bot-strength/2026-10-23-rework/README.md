# v62 BOT: リワーク対応と対策市場への適応

カード定義374枚、初期HP・マナ、構築ルール、ゲームエンジンは変更していない。BOTの購入・行動・局面評価・探索・初期構築を更新した。非公開の相手手札・山札や実際の乱数は判断に使わない。

## 判断の変更

- 固定市場の在庫と価格、公開済みの相手カード、実盤面から、壁・弱化・回復への備えを評価する。市場にあることと相手が既に所有していることは区別する。
- 弱化で攻撃できない小型を追加し続ける評価を修正。解除・除去・全体強化の初購入に必要なマナを確保し、維持用の除去だけでマナ成長が止まるループを避ける。
- ガーディアンの気合と腐敗進行を評価する。気合で残る相手を「この一撃で倒せる」と扱わない。オーラで除去できない相手への空撃ちと、自分の大型を破壊する自動対象除去を避ける。
- 召喚条件を満たせないカードを、所有枚数が増えるだけで得と評価して購入する問題を修正。サーチ・回収・手札整理も現在の使いやすさを参照する。
- 農場・農民・収穫・りんご、訓練所、ゴブリンの支援条件と危険な召喚結果を評価へ追加。りんご・神器の加護の実使用にも対応する。
- Hard/Hellの深い比較では、両者について複数の行動順からターン全体の継続を比較する。平均だけでなく不利なサンプルにも重みを置く。旧バランスの学習済み評価への依存を60%から25%へ下げ、現在のルールに基づく評価を優先する。
- 腐敗小型に偏った旧5/7構築を再選別。Hard5、Hell7はいずれも合法な通常スターターのみ。相互強化、腐敗混成、回復変換、逆算・全体強化の配分を変えた構築を使う。種族の多様さや全合法構築での最適性を保証するものではない。

## 選別と別シード検証

初期案では「除去を増やす」だけの変更が悪化した。実対戦ログから、オーラへの空撃ち、重複した対策札、除去で毎ターンのマナを使い切る問題を確認して修正した。最初の7構築案でもHellの平均がHardより下がったため、弱い候補を採用せず追加比較した。

選別用288試合、最初の再評価896試合、追加6候補384試合などを経て採用構築を固定した。これらは調整用であり、以下の最終検証には混ぜない。初期の不採用案と途中で終了した探索比較も、最終勝率の分母に含めない。

### 同じ旧構築での方策比較: 448試合

旧7構築を固定し、旧/新方策、同じシード・市場・相手・先後を比較。双方のカードルールはv62。簡易方策を使い、相手側は固定された旧方策に弱化・壁・回復の優先行動を追加したもの。実際のHard/Hell探索の勝率ではない。

|市場|旧方策|新方策|
|---|---:|---:|
|自然|28/56|26/56|
|ガーディアン・壁|34/56|43/56|
|回復|45/56|44/56|
|弱化への対策市場|32/56|36/56|
|合計|139/224 (62.05%)|149/224 (66.52%)|

自然・回復での小幅な悪化も含む。全市場での改善は主張しない。

### 採用構築を固定した別シード検証: 1,120試合

旧7構築と新7構築を、同じ新しい簡易方策で評価。5種類の相手、4市場、先後、10シード群を使う。相手には旧腐敗、ゴブリン、混成、弱化2枚、ゴブリン＋弱化2枚を含める。選別後の新しいシード基点は41,000,000。

|構築集合|旧構築|新構築|
|---|---:|---:|
|Hard5|248/400 (62.00%)|318/400 (79.50%)|
|Hell7|328/560 (58.57%)|453/560 (80.89%)|

これは構築の比較であり、Hard/Hell探索の勝率でも対人勝率でもない。特に弱化市場では、Hardが52/100→65/100、Hellが64/140→94/140。無敗ではない。

### 実際のHard/Hell探索: 16試合

同じ相手・2市場・先後で、旧版8試合と採用版8試合を比較。旧/新ともHard4/4、Hell4/4で、勝率改善を証明する標本ではない。全試合完走、不正行動・15秒期限への到達0。採用版の単一判断最大は約2.43秒（Node Worker）。構築はMIXED_RALLYを使用した代表例であり、全7構築の実探索総当たりではない。

相手は公開盤面を見て弱化を使い、壁・回復を優先購入する固定方策。人間の上級者や実探索同士のリーグより限定された検証である。対人無敗・ほぼ勝てない難易度の達成は未測定。

## 機能・実行品質

- 新規13局面群: 弱化からの購入資源確保、ガーディアン除去、重複回避、強化での再始動、気合・腐敗、非公開情報不変、オーラ、自動対象除去、農場・りんご、自己弱化、マナ成長、召喚時自身のオーラ、ゴブリン支援。
- 既存28適応戦略群も成功。全体テスト初回の207/209では購入と弱化対応の2回帰を発見し、修正後に両テスト群を再実行した。配信ガードが最終コミット全体を再検査する。
- ブラウザWorkerでは4難易度、複雑局面、反応選択、途中結果、期限、停止、置換、フォールバックを検証。採用版の重い局面は約9.38秒、別の戦術局面は約5.54秒。画面イベントループは継続した。端末が遅い場合の15秒上限は維持する。
- 既存の大きなビルドチャンクに関する警告は残る。配信後の確認は本番の公開Worker実行で、認証付き対人試遊とは別。

## 再現

依存関係はリポジトリのlockfileで `npm ci`。`baseline.cjs.gz` を作業ディレクトリの `before.cjs`、`candidate.cjs.gz` を `candidate.cjs` に展開し、`BOT_LAB` をそのディレクトリに設定する。出力先には未使用パスを指定する。

- 方策比較: `SEED_BASE=28000000 SAMPLES=4 node ml/bot-strength/rework-gauntlet.cjs <出力.jsonl>`
- 最終構築検証: `COMMON_SEEDS=1 SEED_BASE=41000000 DECKS=<final-decks.json> OPPONENTS=<final-opponents.json> SAMPLES=10 VERSIONS=after node ml/bot-strength/rework-gauntlet.cjs <出力.jsonl>`
- 実探索: `DEADLINE=1 PRODUCT=1 DECKS=<full-decks.json> TIERS=hard,hell MARKETS=wall,suppression SAMPLES=1 SEED_BASE=18000000 ROW_END=16 node ml/bot-strength/rework-gauntlet.cjs <出力.jsonl>`。保存された旧側8行と、最終候補の `VERSIONS=after ROW_END=8` の8行を同じ市場・シード・先後・難易度で対応させている。
- 配信Worker確認: `BOT_ORIGIN=https://yourlore.xyz BOT_QA_OUT=<出力フォルダ> node tests/bot-staging.mjs`。Playwrightを別配置する場合は `LORE_PLAYWRIGHT_MODULE` を設定する。

バンドルとカードのハッシュは `integrity.json`、集計は `summary.json`、各対戦の行動と購入記録は圧縮JSONLに保存。調整用バンドルと結果は最終版と分けている。

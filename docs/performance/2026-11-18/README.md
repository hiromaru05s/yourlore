# HOME・インゲームの軽量化（2026-11-18）

採用済み実装の参照: `a85e12e675177250b0178e4abe9784b7d3a16d91`（作業開始時の `gh/main` と本番ソースが一致）。
作業・実ブラウザー起動元: `/Users/hiromaru05s/.codex/worktrees/performance-1118/LORE_TCG`。本番ビルドをローカルWorkerの `http://127.0.0.1:8798` で検証した。認証・D1・対戦ルームはローカルQA専用。

## 確認した問題と対応

1. **カード一覧の画面外アニメーション**: 430枚中318枚の未読込画像が、画面外でも `artShimmer` を継続していた。スクロール領域をIntersectionObserverで監視し、不可視カードの待機アニメーションだけを休止。スクロールで復帰し、検索・再描画・画面破棄で監視を解放する。デッキのウォッチリストも同じ解放処理を使用する。
2. **メニューから対戦エンジンへの静的依存**: カードの数値表示、対象の所有者判定、チュートリアルのメニュー情報が実行エンジンを読み込んでいた。処理を変更せず `cardStats.ts`、`targetOwner.ts`、`tutorialPartMeta.ts` に分離。従来のエンジン側exportsは維持。初期メニューの依存グラフにエンジンが戻らない回帰テストを追加した。
3. **大きな共通チャンクのキャッシュ更新**: Three.js本体を独立したチャンクへ分割。ゲームデータの更新によるライブラリの再取得を避けやすくした。追加のレンダラーは元の遅延読み込みを維持する。[Rollupの設定仕様](https://rollupjs.org/configuration-options/#output-onlyexplicitmanualchunks)に従い、依存先を無差別に同じチャンクへ取り込まない。
4. **盤面GLBの重複テクスチャ**: 19モデルの埋め込み画像を17個の共有・内容ハッシュ付き画像へ整理。PNGは可逆WebPへ変換。頂点、インデックス、UV、法線、マテリアル、配置を保持した。元の `v1` は制作資料として残し、実行時は `v2-shared` を参照する。直接GLTFロードとバイト列からのparseの両方で解決できる相対テクスチャURIを使用する。
5. **共通UIのPNG**: `stat-cost`、`button-idle`、`portrait-self`、`portrait-opp` を同じ解像度・RGBA画素の可逆WebPへ変換。
6. **ポートレートGIF**: シーカー待機1本とNPCリアクション21本を可逆アニメーションWebPへ変換。全961フレームの表示画素、透過、再生時間、ループ回数を照合。繰り返し被弾時の再スタートと終了・破棄処理を維持する。

## サイズ・処理量

MBは10進数。素材の合計は対象ファイル群のサイズであり、初回アクセスで全て転送される量ではない。

| 対象 | 変更前 | 変更後 | 削減 |
|---|---:|---:|---:|
| 盤面19モデル（共有画像込み） | 15,964,204 bytes | 9,423,095 bytes | 41.0% |
| 共通UI画像4点 | 3,680,400 bytes | 2,498,466 bytes | 32.1% |
| ポートレート22本 | 20,752,461 bytes | 15,250,756 bytes | 26.5% |
| 対象素材合計 | 40,397,065 bytes | 27,172,317 bytes | **13,224,748 bytes / 32.7%** |
| 初期アプリの静的JS依存合計 | 2,563,118 bytes | 2,108,971 bytes | 17.7% |
| 同じJSを同条件でgzip圧縮 | 775,386 bytes | 634,633 bytes | **18.2%** |
| カード一覧の5秒間のTaskDuration | 5.017秒 | 0.094秒 | **98.1%** |
| カード一覧のフレーム間隔p95 | 33.3ms | 16.8ms | 約60fps相当へ改善 |

Chrome実測、1280×800、同じ430枚の一覧、通常モーション。ページはローカル本番ビルド。端末上で他の処理も動作しているため、時間はサービス全利用者の分布やCore Web Vitalsの実測値ではない。同一ページで画面外shimmerを休止する原因切り分けでも、5秒間のTaskDurationが4.980秒から0.019秒へ低下した。HOME、シングル、対戦の値は開幕演出や状態に影響されるため、確定的な速度改善率として扱わない。

Resource Timingの `resourceBodyBytes` はキャッシュから再利用した応答も含む。`resourceTransferBytes` もService Worker内部の全通信を表すものではない。通信削減の確定値は上のファイルサイズと依存グラフで比較する。

## 表示と機能の検証

- 19モデルの全ジオメトリbyte、シーングラフ・マテリアル意味論を比較。旧モデルと新モデルを同じ照明・カメラで描画し、最終比較では19件全て差分0。旧モデル同士の再ロードによる微小な重なり順差も対照として記録した。
- UI画像4点はRGBA byte一致。ポートレート22本はPillowとSharpの独立したデコードで全961フレームの表示画素・時間・反復数が一致。ネイティブブラウザーで21リアクションの表示、再発火、終了、破棄を検証。
- PC／狭い画面でカード一覧の画面外休止、スクロール復帰、キーボード拡大、検索、リセット、言語変更、HOMEへの退出を検証。
- 本番ビルド＋実ローカルWorker/D1/Durable Objectsで、ノーマル・ランク・フレンド・NPC対戦の開始、初手交換、再接続、ターン終了、降参、結果画面、復帰先を検証。
- HOME、カード、シングル、対戦の通常表示を確認。採用済みの `screens/home.ts`、`screens/single.ts`、`ui/duelScene.ts` の画面と演出を基準にした。ゲームルールやモーションの軌道・タイミングは変更していない。
- 全290ファイルの本番テストはデプロイガードでも実行する。追加4件は素材整合、ポートレート全フレーム整合、メニュー依存境界、一覧監視のライフサイクル。既存デッキテストの依存スタブへ新しい破棄関数を追加した。

既存のフォント定義、各ウィンドウ幅のレイアウト、描画密度、カード拡大用原画、サーバーのゲーム処理・インデックスも確認した。フォントのweight/文字範囲、採用済みVFX、盤面形状を減らしてサイズを稼ぐ変更は行っていない。

## 再生成・再検証

Pillow、`cwebp`、`gif2webp` が必要。

```sh
python scripts/optimize-reading-assets.py
python scripts/optimize-portrait-clips.py
npm run typecheck
npm run test:production
npm run build
```

ブラウザーテストは `PLAYWRIGHT_MODULE` を設定し、`tests/reading-assets-parity-browser.mjs` と `tests/portrait-clips-browser.mjs` を実行する。実ローカルAPIの検証と計測は `LORE_TEST_USERS` にQA認証情報ファイル、`LORE_TEST_ORIGIN` にloopback URLを指定して `tests/performance-release-browser.mjs`、`tests/gallery-visibility-browser.mjs`、既存の `local-*-lifecycle-browser.mjs` を実行する。実アカウントの情報をレポートへ保存しない。

制作元を変更した場合は生成スクリプトを再実行する。整合テストは、元画像・モデルと実行用コピーが乖離した場合に失敗する。

# 2026-10-14 — 品質を維持した対戦ロード・CPU処理の軽量化

状態: 軽量化を最新mainへ統合し、2026-10-14にステージングへ反映済み。配信ソース・149件のテスト・101ファイルの一致・実ブラウザ確認は [ステージング記録](staging/README.md) を参照。以下の比較数値・画像は当初のローカル検証記録であり、ステージングでの改善率を表さない。ゲームルール・BOT判断・画質設定・演出のタイムラインは変更していない。

## 実装

- HOMEの画像表示と入場演出が終わった後、アイドル時間に対戦コード、盤面モデル、共通カード枠、開幕素材、効果音、使用デッキの画像を準備する。BOT難易度選択・マッチング待機でも準備を始める。画面を離れた場合は未開始の予約を破棄する。
- 画像は全体で最大8件、うちバックグラウンドは最大2件。必要になった素材は待機列の先頭へ昇格し、同じURLは一つの処理を共有する。画素を保持するキャッシュは32 MiBまで。画素の解放後も読み込み成功の記録は維持する。
- 盤面モデルは実際の表示と同じURL・リビジョンで先読みし、最大32 MiBのバイトキャッシュを共有する。各盤面の形状・材質・テクスチャは個別に生成／破棄するため、別の対戦のリソースを破棄しない。
- 共通画像の読み込みと盤面組み立てを並行化。実盤面の最初の描画後に画像を調査し、`display:none`の素材・その子孫を待機対象から除外する。`visibility:hidden`／`opacity:0`の開幕用素材は対象に残す。ブラウザが初期DOMのCSSから自動取得する旧素材のリクエストすべてを削除したわけではない。
- 準備済みのカード画像しかない状態更新では、画像待ちによる操作ロックを挟まない。次のドローに備えて自分のデッキ画像を準備する。相手の非公開領域からは画像を先読みしない。
- 山札・墓地・移動カードの角丸形状を一度だけ三角形へ分割し、独立した頂点バッファへコピーする。頂点数・厚み・UV・材質を維持する。
- 傾き・光沢の入力を画面更新ごとにまとめ、同一フレーム内の繰り返しレイアウト測定を除去する。
- 一時的な画像失敗は2回自動再試行し、その後に手動再試行を表示する。共有転送は呼び出し元の短い待機期限では中断しない。再試行UIの所有者は一つにし、キャンセル・画面破棄時に待機を終了する。

## 計測

Chrome headless、横幅1280／390px、高さ900px、DPR 1、10 Mbps・遅延40ms・CPU 2倍制限。毎回新しいブラウザコンテキスト。APIはfixture、画像・音声・モデルは実ファイル。HOME表示後に両版とも12秒待機し、BOT開始クリックから3D盤面・画像の準備完了までを計測した。**承認済み開幕演出の時間を短縮する変更は含まない。**

| 項目 | 変更前 | 最終版 | 差分 |
| --- | ---: | ---: | ---: |
| PC幅の盤面準備 | 25.095秒 | 9.080秒 | 63.8%短縮 |
| スマホ幅の盤面準備 | 16.151秒 | 11.871秒 | 26.5%短縮 |
| PC幅・開始後の計測窓内の通信量 | 31.68 MB | 15.13 MB | 約52%減 |
| スマホ幅・開始後の計測窓内の通信量 | 26.59 MB | 17.09 MB | 約36%減 |
| 山札／墓地150組の生成・破棄（5回の中央値） | 213.84ms | 80.64ms | 62.3%減 |

通信量は開始後から盤面準備完了＋12秒までのリソースを集計し、HOMEで先読みした通信は含まない。先読みで通信の時点を前へ移した効果を含む。BOTのデッキ・先手・マーケットはランダムで、単発のブラウザ比較である。全操作・全端末の速度がこの割合で改善するという意味ではない。

共有マシンに強い同時負荷があり、最終計測時のHOME表示はPC幅9.84→11.35秒、スマホ幅8.25→19.06秒と大きく揺れた。先読み開始はHOME表示完了後であるが、この計測からHOME起動の改善・無悪化は断定しない。以前の反復ではHOMEはおおむね8〜10秒だった。実端末・実回線での追加比較は未実施。

実盤面の5秒待機描画では、P95フレーム間隔はPC 16.8→16.7ms、スマホ16.7→16.8ms。最終サンプルの全盤面再描画は両方0回で、静的盤面のキャッシュを維持。リフト・ターン表示の描画は継続している。GPU負荷全体の大幅削減や全VFX同時再生での60fpsは主張しない。

## 検証と証拠

- `tests/loading-cache.mjs`: 優先順位、背景同時数、途中の昇格、共有画像、失敗後の再試行、画素解放後の転送記録、モデルのURL一致・再利用・容量上限。
- `tests/loading-readiness.mjs`: 非表示素材の除外と開幕素材の保持、低速共有転送、手動再試行中のキャンセル、画面破棄、対戦の再試行UIが1つだけで復帰すること。
- `tests/pile-geometry-cache.mjs`: 凍結した変更前実装と32条件を比較。頂点・法線・UV・インデックス・配置・材質属性が一致。別インスタンスの変更／破棄が他へ影響しないこと。
- `tests/loading-interaction-browser.mjs`: 200回のpointermoveを1回の矩形測定に集約し最終の傾き値が一致。pointerdownによる予約破棄。実モデルを複数回parseしても再取得せず、形状・材質は独立。
- `tests/duel-ui.mjs`: ゾーン・トラップ・購入・ターン制約・マナ・HP・手札・画面サイズの回帰テスト。JSDOMにCSSを適用するテストではないため、bundlerのCSS読み込みを空にし、公開フォントURLの解決エラーを回避した。CSS・3Dは実ブラウザ側で確認。
- 製品エントリポイントから到達するコードのTypeScriptチェックとVite production bundleを確認。全体の`npm --workspace client run typecheck`は着手前からの試作ファイル9件のエラーで失敗するため、全体成功とは扱わない。
- 当初のローカル検証とは別に、ステージングは後段の記録で確認。認証済みオンライン対戦、本番、低性能スマホ実機は未検証。

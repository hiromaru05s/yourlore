# 初回HOMEの読込短縮（画質・演出を維持）

直前の本番ソース `74bac32562c5e8191bdf2ff6c5dbefc65a85f2ae` と、その公開記録を含む main `f6bbd45e` を基準に追加改善した。前回のページ移動・モード切替改善を保持する。

## 変更

- HOMEボタン生成時から採用済みの `home-duel-button` クラスを付ける。旧CSSの背景をこのボタンから除外し、最終表示に使わない `stage-v1/sigil.png`（1,996,219 bytes）と `duel-ink-v1/disc.png`（1,787,283 bytes）の先行ダウンロードを止める。
- 共通パネルを可逆WebP化。1536×1024のまま、可視RGBA画素の相違は0。1,439,532 → 732,638 bytes。PNG原本も保持。
- 起動用画像11枚をビルド時に内容ハッシュ付きURLへコピーし、HTML・CSS・DOM・GPUの参照を揃える。画像内容はそのまま。既存の `/assets/*` immutableキャッシュを利用し、更新時はハッシュが変わる。
- 背景のThree.jsテクスチャとモード色は共通の復号済みImageを使う。別ローダーによる同一画像の再取得・復号を避ける。既存の32 MiB画像保持上限と失敗時の再試行を保持する。
- 3モードの色を初回HOMEで揃える条件、4秒の入場演出、流墨・水面・雲・蔦・光・精霊の描画内容は変更しない。

`tests/first-boot-browser.mjs`。Chrome、1280×900／390×900、DPR 1、10 Mbps、40 ms latency、CPU 2倍減速。Service Workerは無効、APIはfixture、静的素材と描画は本物。キャッシュなし→同じブラウザで再読込を各1回。ローカル配信にも本番相当のCache-ControlとETag/304再検証を設定した。時間には既存の入場演出を含む。実機・認証済み実利用の性能保証ではない。

## 検証

- `startup-assets.mjs`: 出力画像が元ファイルのバイト列と一致、内容SHAによるURL、再ビルド時のURL安定性、CSS/DOMの置換一致。
- `loading-cache.mjs`: GPUへ渡すImageが既存の復号済みImageと同一で、追加生成しない。
- ブラウザの初回／再読込で、旧画像の取得なし、起動用画像の実転送は最大1回、再読込ではimmutable画像の再転送なし、3モード切替とページエラーなしを確認。
- パネルの画素一致は `panel-pixels.json`。HOMEの採用フレーム・原画・背景・共通UIを前後の実画面で比較。連続描画のシェーダーと時間軸は変更していない。
- 検証起動元: `/Users/hiromaru05s/.codex/worktrees/startup-load-optimization/LORE_TCG`。同ディレクトリの `client/dist` と、基準ビルド `/tmp/lore-first-boot-before-dist` をテスト内HTTPサーバーで配信。

型チェック・ビルド・回帰テスト **249/249** 成功。既存の `startup-navigation-browser.mjs` でPC／狭い画面のモード切替・カード／デッキ移動・コンテキスト再利用・全画面ロード0回を確認。`startup-failure-browser.mjs` で画像遅延中の離脱、デッキ操作、GPU喪失・非対応時の静止画を確認した。本番公開結果は公開後に追記する。

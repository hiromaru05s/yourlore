# 腐敗：承認済み②の溶解のみを適用

2026-10-07。ユーザー指定「雫が落ちる効果いらない」「シンプルに溶け切って…手前までを一つの完成したアニメーションとして適用」「ステージングに」。

- 前稿②「蝕孔の崩壊」の13箇所の腐食・色・時間カーブを `client/src/ui/decay/fixed-face.ts` に保持。カード面だけが溶け切る2.08秒。雫、毒溜まり、残留膜、シェルフへ飛ぶ後半は付けない。
- ランタイムのカードキャプチャは余白を除去し、元カードの全面と同じ投影へ配置する。カードの裏面全体が盤面に接する。空中落下や画面下方向への重力はない。
- `addDecay` の破壊だけが `destroy.cause='decay'` を持つ。実際に破壊されなければイベントは出ない。保護、腐敗の閾値未満、通常撃破、オーラ消滅による巻き添えは従来のルールを維持。token/voidの行き先も保持。
- 共有のBaseControllerが通常盤面・同一バッチ内の召喚カード・両プレイヤーの表示を振り分ける。腐敗は溶解で完了し、通常の破壊・マナ演出に重ねない。シェルフ／リフトの状態・3ダメージはエンジンの元の結果を使用する。
- 中断、早送り、画面非表示、リサイズ、ページ離脱、DOM除去、キャプチャ中の中断、低減モーション、テクスチャ／WebGL失敗を処理。カードを復元して呼出側の最終状態更新に渡し、canvas・GPU・タイマーを解放する。
- 低減モーションは即時の状態更新。描画素材が使えない場合だけ短いネイティブ消失を使う。通常経路の見た目を変更するフォールバックではない。

## 検証

`tests/decay-dissolve.mjs`: エンジン原因判別、閾値、保護、token、両所有者、オーラ連鎖、通常撃破、イベントJSON、非同期中断・低減・欠損素材の後片付け。現行production suiteに追加。

`tests/quick-playback.mjs`: 腐敗フラグによる共有controllerの振り分けと既存クイック処理。

`tests/decay-browser.mjs`: `client/decay-adoption.html` の開発専用ハーネス。実エンジン→controller→描画→シェルフ／HP更新をPC・スマホ・両所有者で確認する。採用ハーネスは通常ビルドには含めない。

ステージングは既存 `scripts/deploy-guard.mjs staging` を使用。リモート最新main、公開済みソースの祖先関係、ロック、確定スナップショットの型検査・全production suite・ビルド・Worker再確認を経由する。`staging/` のローカル記録に、公開ソース・Worker・実配信バイトとブラウザ検証を保存する。

機能検証、ユーザー承認済みの表現、配信ハッシュ、実ブラウザの再生、認証オンライン対戦は別の証拠として扱う。本番公開は対象外。

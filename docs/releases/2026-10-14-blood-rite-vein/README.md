# 血鬼術 02「血脈の鼓動」

2026-10-14のユーザー指定「０２で適用して。ステージングあげて」による通常経路への採用。

承認された `blood-rite-five` の②だけを `ui/bloodRite` に切り出した。体力バッジの外周に根を持つ血脈が内側へ脈動し、暗い芯・赤い色面・細い湿った反射を残す。元のHP盾形状と数字をマスクで保護する。比較版にあった350msの発動前待機を除き、形状と発動後の時間設計を維持した。

魔法ダメージの回復反転をengineで確定したとき、healイベントに発動元カードUID群を付ける。controllerが専用演出を一度だけ実行し、汎用残存魔法演出・通常回復フラッシュとは重複させない。発動から420msで表示HPを更新、1550msで終了。同じ時計で実カードを最大1.075倍・見かけ上2〜6px浮上させ、1190msまでに元のスタイルへ戻す。

回復倍率、切り捨て、盾・無効化の優先順位、通常の回復ルールは維持。補正後0回復の場合も血鬼術の発動を示すが、回復に付随するゲーム処理は起動しない。複数の血鬼術があれば正確な発動元を全て動かす。同一カードの同時発動は拡大率を加算しない。

早送り・画面非表示・リサイズ・盤面破棄で描画を中断し、カードのinline styleを復元。HP更新は一度だけ完了する。低減モーションでは血脈の大きな運動とカードの浮上を省く。

## 検証

- `npm run typecheck` と `npm run build`。

- `node tests/critical-trigger-chains.mjs`: 既存の回復連鎖を含む11条件。
- `tests/blood-rite-browser.mjs`: 実controller/reducer/GameViewでPC・390px、両陣営、完全な詠唱経路、同時発動、早送り、非表示、リサイズ、対象削除、低減モーション。画像・記録はQAフォルダへ保存。
- 公開は `scripts/deploy-guard.mjs staging` によるコミット固定の全テスト・ビルドを使用。リリース後に `scripts/check-blood-rite-staging.mjs` でHTML・全JS/CSS・カード面・体力アイコンのSHA-256一致を確認する。

# ギャンブラー 01 / 伝説のギャンブラー 02 採用

2026-10-09 ユーザー指定: 「０１はギャンブラー」「０２は伝説のギャンブラー」。召喚前に生のカードを表示する前段を除き、最初のフレームから演出として表示したうえでステージングへ反映する依頼。

## 変更

- `GAMBLER` → 王金の鋳盤 (01)、`LEGEND_GAMBLER` → 象牙の虹彩 (02)。出目判定、ターン開始能力、カード性能は変更しない。
- `focusSummon` の生カード拡大と、`flyIntoSlot` の生カード転送を2枚だけ省略。通常の summon dispatcher を通して専用ランタイムを呼び、一般召喚と重ねない。
- 元の3400msタイムラインの冒頭850msを除き、最初から体積と専用材質がある状態を描画。形成・回転・復元の残り2550msは同じ形状・動き。
- ソースを同期的に隠し、frame 0 を描いてからDOMへ設置する。カード表面の非同期キャプチャ前にも完全に不透明な回転盤を描画する。カードの画像が違っても最初の描画は同一で、後半の復元でのみ元カードへ戻る。
- 遅いキャプチャはカード復元前の時刻で待つ。中断、リサイズ、タブ非表示、低減モーション、失敗時はネイティブカードへ復帰する。
- 同時召喚はWebGLレンダラーを共有し、カード面ごとにテクスチャを分けて解放。比較ラボも同じ共有実装を参照。

## 検証

- `node tests/gambler-summon.mjs`: 待機中キャプチャより先のframe 0、2枚の割当、接触1回、3枚同時、中断・detach・resize・非表示、低減、失敗時復帰、資源解放。
- `node tests/gambler-summon-browser.mjs`: 実際の `playMonster` / `summonFromHand` / `ghostSummon` を2カード×両側=12通り。最初のDOM設置時点の時刻0・描画済み画素・生カードゴースト0・一般召喚との重複0を確認。390px、低減、skip/cancel/resizeも検査。結果は `qa/runtime.json`。
- 2種類の無関係なカード画像でframe 0が同じ画像になること、終端では異なるカード画像に戻ることを実レンダラーで検査。
- `gambler-runtime.html` は開発用。通常配信のエントリには含めない。
- 品質判断: 01/02はユーザー選択済み。今回は未変形カードの前段を省略した修正で、選択済みの材質・回転・復元構成を保持した。機能検証と再承認は別。

ステージングのバージョンと資産ハッシュは公開後の記録で確認する。認証済みオンライン対戦の実プレイとは区別する。

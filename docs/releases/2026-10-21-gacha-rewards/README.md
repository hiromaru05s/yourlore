# ガチャ結果 — 報酬そのものを見せる

2026-10-21。ユーザー指示: スターターはフレームを含め、スリーブ・墓地＆デッキ置き場・エフェクトは種類に合う特別感を持たせて作り直し、本番へ公開する。

## 原因と変更

`gachaCinematic.ts` が全報酬を560×800の「画像＋文字」の独自カードへ変換し、`rewardKind='sleeve'` で描画していた。スターターの本来のフレームも、家具の立体形状も失われていた。結果・履歴も共通の画像タイルだった。

魔導書の飛来・開頁と秘字の光潮は保持。結果の顕現を実物の表示へ接続し、以下の五つの構成を使い分ける。

1. スターター: 共通 `cardEl` の完全なカード面。832pxのマスターアート、枠、コスト、カード名を維持。
2. スリーブ: 奥の二枚と中央の一枚が段階的に開く構図。中央には装備時と同一の動く表面を描画。複製は見本であり、付与枚数は変更しない。
3. 家具: 横長の舞台に、実盤面で使うデッキ置き場・墓地の二つの立体モデル。時間差で接地し、影と材質の動きもモデルへ追従。
4. エフェクト: 宝箱カードを見本に、獲得した実エフェクトを適用。実際に付与したものと、表示用カードを明記して区別する。
5. 一覧・履歴: 縦長の完全カード／スリーブ、横長の家具、動くエフェクトをそれぞれの比率で配置。選択すると同じ専用表示で確認できる。

10連はサーバー順を保ち、番号・前後ボタン・左右キーで個別確認。重複還元と所持数を表示する。演出のロード中にも結果へ進める。閉じる、切り替え、低減モーション、非表示、後始末を扱う。経済、確率、抽選、所持権限、購入リクエスト、履歴保存のサーバー処理は変更していない。

## 品質判断

`docs/animation-quality-benchmark.md` の②の映像と連続フレームを参照。主役の面と輪郭を維持し、光・開き・接地を実物へ結びつける判断を適用した。粒や環を追加する方法は採用していない。既存の魔導書から結果へは750msの重なりを持ち、表示開始から約1.2秒で同じカード面が読み取れる状態へ落ち着く。スリーブの扇は1.4〜1.6秒、表面の一度きりの反射は1.8秒。家具は1.4秒で二つのモデルが接地する。

- `qa/reveal.mp4`: 実ショップ導線の通常速度録画（魔導書→カード→スリーブ→家具）。`qa/reveal-sequence.jpg` は同映像の連続フレーム。
- `qa/*desktop.png`, `qa/starter-390.png`, `qa/overview-mobile.png`: 実UIとマスター素材の表示確認。
- `qa/board-reference.png`: 同じ葉織素材を使う白い実盤面レンダラー。相手側の空の置き場と手札を確認。
- 見た目の自己レビューで、PC家具の小ささ、横画面の操作重なり、一覧CSSによるカード絵のcontain変形を発見して修正。
- 機能テストの成功をユーザーの見た目承認とは扱わない。今回のユーザー指示に基づく完成版として公開する。

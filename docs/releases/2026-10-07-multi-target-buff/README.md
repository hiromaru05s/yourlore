# 複数対象バフの演出漏れ修正

支援ラッパの対象選択では、次の選択が前の演出を早送りし、盤面再描画でそのカードの演出元DOMが破棄されていた。修正前の実コントローラー／エンジン再現では、3体選択後に残る演出は最後の1体だった。

- `buffTurn` の対象選択中は、カードごとの変化前の実効能力値を保持する。選択完了・途中キャンセル後に、実際に変化した全対象で既存のバフ演出を同時再生する。
- `GameView.render` が返す全対象の演出完了をコントローラーのイベント処理に含め、BOTなどの後続処理による早期中断を防ぐ。ユーザーの明示的な早送りは維持する。
- エンジンの能力値・選択ルール、青い上矢印、カード面の変形と光、再生速度は変更しない。

## 機能確認

型検査と production suite 55/55 合格。実エンジン・コントローラー・GameView を使う Chrome テストで、両陣営の支援ラッパ3体、2体での早期選択完了、途中キャンセル、連続3入力、全体バフ7体、390px、低減モーションと破棄時の後片付けを確認。フレームごとに全対象の演出と矢印キャンバスの可視画素を数え、全対象の完了前に処理が終わらないことを検証する。

## 見た目の確認

`qa/playback.mp4` は実盤面の通常速度での連続再生。PC／スマホ、両陣営、3体／7体で既存のカード面と青い矢印が各カードに追従する。造形の新規制作・品質の再承認ではなく、承認済み演出の再生対象と完了待ちの修正。静止画と機能テストのみを動きの品質承認として扱わない。

`tests/multi-target-buff-staging-browser.mjs` はデプロイ後に全JS/CSSのSHA-256を照合し、既存のコスメ確認用実盤面から本番バンドルのコントローラーを実行する。ステージング側は状態スナップショットを用いるテストであり、認証付きオンライン対戦の検証ではない。

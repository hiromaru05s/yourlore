# 腐敗カウンター 01「菌糸の侵蝕」採用

2026-10-12、ユーザーの「０１でステージング適用して」に基づく採用。
対象はカード全面への改稿後の01。比較版 `docs/vfx-prototypes/2026-10-12-decay-counter-four/qa-v2/` を選択時点の参照として保持する。

## 接続

- `ui/decayCounter/` に01の表面描画だけを切り出し、額縁・絵・菌糸・細い濡れた縁・実際のカウンター札への収束を維持する。尺2100ms、表示更新1680ms。3個以上も値を丸めない。
- エンジンの `addDecay` が実際に増加した時だけ `decayCounterGrant { player, uid, before, after }` を発行する。ダメージ、破壊、耐性などのルールは変更しない。公開フィールドの結果として、既存のWebSocketイベント転送にも乗る。
- 通常カードと同一バッチ内の召喚カードを共有controllerから再生する。召喚の見た目に最終カウンターを先出ししない。複数カードへの連続付与は同時に開始するが、破壊・別の反応・同じ対象への再付与を越えてまとめない。
- 3個目の付与は①を完了してから、既に承認済みの腐敗崩壊へ進む。破壊を防がれた時は付与だけ再生する。
- 1個のWebGLコンテキストと4枚分のアトラスを共有する。カードの名前・数値・能力表示を生かし、状態数は変化時だけ書き換える。
- スキップ、低減モーション、中断、非表示、リサイズ、DOM除去、画面破棄、キャプチャ・WebGL失敗でも、確定済みのカウンターに表示を揃えて片付ける。ゲーム状態の確定をアニメーション完了まで遅延させない。

## 検証範囲

- `tests/decay-counter-grant.mjs`: 両所有者×元の個数0/1/2×追加1/2/3、JSON転送、破壊前の順序、破壊保護、古いカウンターによる再発火防止、3言語、低減、中断、置換、欠損素材、後片付け。
- `tests/quick-playback.mjs`: 通常カード／召喚直後のカードで付与1回→腐敗破壊1回。連続する複数対象の同時開始と、同一対象への次の付与を待つこと。
- `tests/decay-counter-browser.mjs`: 実際のreducer→BaseController→本体レンダラーを開発用の実盤面で確認する。選択された比較版と本体版を6時刻でピクセル比較。両陣営、閾値、破壊保護、PC／モバイル幅、3対象、中断と破棄を含む。
- 通常速度の観測はページ内の描画ループで行う。負荷の高い環境では、外部からDOMをポーリングする方式が短い演出を見逃したため、試験の観測方法を修正した。描画の尺を伸ばして試験を通してはいない。

機能試験、見た目の観察、ステージングの配信ハッシュは別の記録として扱う。認証済みオンライン2者対戦や実機スマホの検証は、この開発用盤面試験に含めない。

ローカル実盤面の16試験群が通過し、選択版との6時刻の描画差分は0。型検査とビルド、専用ルール・後片付け試験、controllerの順序検証も通過。静止画の確認では、カード全面の侵蝕が元の絵と縁に追従し、隣接カードや能力札を覆わないことを確認した。機能検証の成功とは分けた見た目の観察である。

`qa/continuous.mp4` は通常速度での0→1付与の連続収録。両陣営の3個目→既存崩壊は `qa/collapse-*.png` と実盤面試験のイベント・描画検証で確認している。

対象はカード全面への改稿後の01。比較版 `docs/vfx-prototypes/2026-10-12-decay-counter-four/qa-v2/` を選択時点の参照として保持する。

## 接続

- `ui/decayCounter/` に01の表面描画だけを切り出し、額縁・絵・菌糸・細い濡れた縁・実際のカウンター札への収束を維持する。尺2100ms、表示更新1680ms。3個以上も値を丸めない。
- エンジンの `addDecay` が実際に増加した時だけ `decayCounterGrant { player, uid, before, after }` を発行する。ダメージ、破壊、耐性などのルールは変更しない。公開フィールドの結果として、既存のWebSocketイベント転送にも乗る。
- 通常カードと同一バッチ内の召喚カードを共有controllerから再生する。召喚の見た目に最終カウンターを先出ししない。複数カードへの連続付与は同時に開始するが、破壊・別の反応・同じ対象への再付与を越えてまとめない。
- 3個目の付与は①を完了してから、既に承認済みの腐敗崩壊へ進む。破壊を防がれた時は付与だけ再生する。
- 1個のWebGLコンテキストと4枚分のアトラスを共有する。カードの名前・数値・能力表示を生かし、状態数は変化時だけ書き換える。
- スキップ、低減モーション、中断、非表示、リサイズ、DOM除去、画面破棄、キャプチャ・WebGL失敗でも、確定済みのカウンターに表示を揃えて片付ける。ゲーム状態の確定をアニメーション完了まで遅延させない。

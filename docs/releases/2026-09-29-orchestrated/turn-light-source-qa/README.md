2026-09-29。ユーザーが①「蒼白の磁器」を選定し、通常対戦の標準表示に採用。ローカルコードへの適用済み。デプロイは未実施。

## ①の採用

`client/src/ui/turnLight.ts` を通常対戦から読み込むようにし、プレビュー指定なしで①が有効になる。比較用のdevモジュールは同じ実装を再公開する。操作可能時の発光、無効/相手ターンの消灯、警告色、発色を保つ描画経路、タップ領域と文字色を標準CSSに移行。

通常のGameViewを使う `duel-lab.html?polish` で、プレビュー指定なしの①表示・Enterによるターン終了・スマホの投影後44px以上を検証。`qa/adopted-desktop.png` / `qa/adopted-mobile.png` に保存。型チェックとproduction buildも確認。

## 第3稿: 比較と実盤面の発色を一致させる

ユーザー指摘の「画像では良いがインゲームで違う」は実際の差だった。上段は標準材質をAgX処理した後、toneMapped=falseのカスタム発光を直接描画。実盤面は発光まで線形HDRキャッシュへ合成した後、全体にAgXを適用していたため、発光と背後の色が一緒に白く圧縮されていた。照明方向も比較側と異なっていた。

実盤面のプレビューボタンだけ専用レイヤーへ移し、盤面キャッシュの表示後に比較と同じ色処理・照明で描画する。ボタン周辺に絞った深度のみのパスを先に描き、押し込み時の台座との前後関係を維持。盤面の色処理・他のUIは変更していない。第3稿時点では比較用のみ。①採用後は通常対戦でもこのパスを使用する。追加のライト・深度材質と元のレイヤーは終了時に解放・復帰する。

`tests/turn-light-parity-browser.mjs` は同じGLB・カメラ・照明・時刻1234ms・残量64/90で、上段の直接描画と実盤面のキャッシュ＋ボタン描画をRGBAで比較。3案×自分/相手の6条件すべてで最大差 **1/255**、平均差 **0.00035/255以下**。これは描画経路の同条件比較で、実際の上下プレビューのカメラ角度・表示サイズ・既存台座まで同一にしたという意味ではない。

`qa/actual-board-three.png` は実盤面スクリーンショットからの切り出しと2倍拡大。加工による色変更はなし。前稿の白っぽい実盤面画像を `revision-2/` に保存。

## 第2稿: 発光を大幅に強化

ユーザーの「まだ控えめ」「もっと大袈裟に光ってもいい」を受け、3案共通で白熱する縁、強い表面発光、周囲へ漏れる色付きの光、約3.7秒周期の明暗を追加。金紋の巡回・青い内部光も強化した。新しい光の面はPRESS_CAPに直接取り付け、押し込み・回転に追従。中心は透明で文字を保護し、タイマーの暗い目盛りが残るよう明るい帯の幅を調整した。

初稿のコード・比較画像・動画は `revision-1/` に保存。現在の `qa/` は第2稿。

## 品質基準の翻案

着手前に `animation-quality-benchmark.md`、`vfx-art-direction.md`、銀紋の流墨の800ms画像と動画を4fpsに展開した連続12フレームを確認。元の表面・輪郭を維持して、暗部・面・細い明部を別に構成する考え方を適用した。ボタンに流墨そのものは追加しない。

光は GLB のローカル表面座標で計算し、PRESS_CAP の押し込み・回転に追従する。タイマーは既存24個の目盛りの中に芯と縁を作り、残量の末端に局所光を集める。減少は秒の更新に合わせ、目盛りの途中まで表現する。近傍への光のにじみはタイマーの実位置に固定した小さな面で描く。独立した粒子や大きな環は追加していない。

- 相手ターン・disabled: ボタンの発光を消し、暗い赤／灰色へ切り替える。
- タイマー: 15秒以下で橙、5秒以下で赤。0では全目盛りを消灯。
- 操作: 元のHTML buttonのdisabled/クリック/キーボード判定を維持。開発プレビューでのみ最小タップ領域を拡大。
- 低減モーション: 新しい表面光の時間を固定。上段の押下動作も省略。既存盤面の押下回転は元実装のまま。
- 更新: 新しい発光による実盤面再描画要求は最大約30fps。数値や状態変更は即時反映。
- 終了: 元マテリアルを復帰し、追加マテリアル・タイマーのにじみ・ボタン発光面のgeometryを解放。

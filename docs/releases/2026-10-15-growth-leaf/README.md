# 成長01「双葉の息吹」採用

2026-10-15のユーザー指示「01でステージングあげて」による通常対戦への接続。

第2稿01の葉の形状・陰影・葉脈・開閉動作を `ui/growth/visual.ts` へ抽出。カードから伸びる形状、カードとHPを結ぶ線、粒子の飛翔は使わない。成長のカード面を短く点灯させ、回復演出はHP周辺で完結する。

## 通常経路

- `drawN` が実際に発生した正の回復へ `growthSourceUid` を付ける。回復量やルールは変更しない。ハイエルフで0になった後の普通の回復を成長と誤認しない。
- 成長を含むバッチのドローは、手札だけを先に描画して既存のカードドロー演出を使用。HP・盤面・他の効果を最終状態へ先に進めない。相手は裏面のまま。
- 連続する成長だけを共通時計へまとめる。摩耗、幽霊、他の回復や誘発を横断しない。カードごとの再誘発は250ms、異なる成長個体は85ms間隔。
- 通常の永続発動・回復演出との二重発火を抑止。回復音とHP更新は葉のピークで一度だけ実行。
- 既存 `boardMotionScope` による高速送り・画面変更・非表示・破棄のキャンセルに接続。回復の反映は中断時にも一度ずつ保証。元カードのstyleは変更しない。

## 検証

`tests/growth.mjs`: 両陣営×成長1/2枚×ドロー1/3枚×回復半減/標準/倍化の24ケース。0回復と後続通常回復、摩耗との境界、ドロー後の自己ダメージ、空デッキ、別プレイヤーの回復、分割ドローも検証。production suiteに追加。

`tests/growth-browser.mjs`: 実GameViewと実BaseControllerで6盤面ケース（摩耗との同時設置を含む）の再生順、HP更新、相手の裏面、重複・キャンセル・低減・390pxを検証するブラウザーテスト。認証付きオンライン対戦の証拠とは区別する。

ステージングの公開結果は同ディレクトリの `staging.json` と検証ログで記録する。公開は `scripts/deploy-guard.mjs staging` に限定する。

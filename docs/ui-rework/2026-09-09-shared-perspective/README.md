# 対戦画面の共通視点・寸法修正

台、Blender製マーケット、デッキ台、シェルフを単一の透視カメラとライトで描画。DOMカード・ゾーン・円形タイマー・終了ボタンにも同じ投影を適用した。以前の各家具専用カメラとマーケットの正投影が、見え方の不一致の主因だった。

- 基準カード比率0.64。マーケットとモンスターは同じ物理寸法・通常フレーム。奥と手前の画面上の大きさは透視投影に従う。
- デッキ台幅1.3カード幅、シェルフ幅2カード幅。GLBの寸法規約から配置し、家具ごとの画角合わせでカードを縮めない。
- 魔法罠は14枠を維持し、7枚のモンスター列に対応する半幅の状態カード列とした。
- キャラクターは従来の1.5倍。キャラクターと盤上カードの重なりを避ける専用余白を確保。
- 砂時計のDOMと3D描画を削除。円形タイマーと終了ボタンは共通の盤面投影。
- 共通光源・接地影・透視カメラの深度範囲を調整。薄いカード表面のZ-fightingを解消。
- 召喚・永続魔法の連続着地も共通投影を参照。

## 検証

`tests/board-perspective-browser.mjs` は実ブラウザのDOM矩形を独立したThree.jsの透視投影と比較。前後のデッキ、前後のモンスター列、マーケット、操作部で2px未満を要求。実測は `browser-checks.json`。

1280×720、1920×1080、390×844を画面確認。最大7モンスター・14魔法罠、30マナ、棚のカードを表示。攻撃中のUI、矢印の固定始点、両陣営の召喚・永続魔法着地、ダイス、キャンセル・破棄後の清掃を確認。

既存の `duel-ui`、家具GLB、dice-model、library-piles-browser、enchantment-drop-browser テストも通過。山札補充、手札ドラッグ、タッチによる永続魔法、非公開罠、GPUなしのフォールバックを含む。`duel-polish-browser` は新しい包括テストへの互換入口。

ビルド成功。既存の大きなJSチャンク警告は残る。長時間の実機モバイル負荷・オンラインPvPの全効果組み合わせは今回の検証範囲外。

# デュエル開幕 v1 — ローカル実装

2026-09-27。基点 f297070。提案 `docs/design/2026-09-27-duel-opening-plan.md` の最初の実装。

## 見る

- `npm --workspace client run dev -- --host 127.0.0.1 --port 5197`
- http://127.0.0.1:5197/duel-lab.html?opening — 再生、先攻／後攻、時刻指定のプレビュー。再生ボタンは音声のジェスチャー解除も行う。
- http://127.0.0.1:5197/duel-lab.html?live — 通常のLocalControllerによるBOT対戦。

## 実装

- 5.8秒の一つの時間軸で、二人のカットイン、実肖像への移動、コイン、先攻結果、両者3枚ずつの配札を進める。
- 人物は既存の確定済みゲーム内イラストを使用。背景込みの大きな肖像を動かす2.5Dの初版であり、専用の身体動作クリップ、髪・布の個別アニメーション、ボイスは未制作。
- コインは既存メッシュを盤面のThree.jsシーンへ取り付け、同じカメラ・照明・影を使う。先攻結果を再抽選しない。コインの動きだけで盤面DOMの配置を毎フレーム再計算しない。
- LOREオリジナル音源7ファイルをdd855a4から選択して同梱。主音量、ミュート、ジェスチャー制約を共用し、スキップ・破棄で開幕音を停止する。`client/public/sfx/opening-v1/manifest.json` に元コミット・hash・音量測定値を保存。
- 配札にAbortSignalを追加。退出、resize、背景移動、スキップで演出を終了でき、手札と入力状態を復旧する。
- WebGL不可では2Dコイン、reduce-motionでは静止結果表示に切り替える。画像・盤面準備待ちは期限付き。
- 新規オンラインルームは準備通知を両者から受け、共通の開始時刻を確定。サーバーはその時刻までゲーム操作を拒否し、初手の時計を開始しない。準備は最大8秒、通常演出5.8秒。開始時刻は永続化し、再接続・重複通知でリセットしない。
- 片側スキップは操作開始を早めない。古いクライアントとの混在ルームは既存方式へ戻し、新クライアントは旧サーバーの進行中ターンで長い開幕を追加しない。
- ホーム、既存盤面モデル、カード内容、バランス、エンジンの先攻・初期手札規則を変更していない。

## 検証

- `npm run build` — 成功。既存の大きいbundle、およびcoinSceneの静的／動的importに関する警告あり。
- `npm run typecheck` — クライアント・サーバー成功。
- `node tests/duel-ui.mjs` — 既存UI回帰と開幕中に時計を開始しない検証、成功。
- `node tests/duel-opening-server.mjs` — 実GameRoomクラスに模擬ストレージ・ソケットを接続。両者準備、入力拒否／解除、時計、再接続、休眠復元、タイムアウト、重複alarm、ランクのマーケット確認、既存alarmとの併用、旧クライアント、相手手札の秘匿を検証。成功。
- `PLAYWRIGHT_MODULE=/tmp/lore-opening-tools/node_modules/playwright/index.mjs node tests/duel-opening-browser.mjs` — Chrome。1280×720、1920×1080、390×844、844×390、再生／停止／スキップ、両方の先攻結果、3枚の配札、reduce-motion、BOT用実controller、オンライン用clientの待ちと500秒の時計差、WebGL不可を検証。成功。`browser-report.json` に記録。
- `git diff --check` — 成功。

画像は各画面寸法のfaceoff／coin、`deal.png`、`opponent-first.png`。ローカルの録画は `recordings/` に保存。プレビュー操作パネルは画像撮影時のみ隠す。

サーバー側は模擬環境、クライアント側は実ブラウザーで検証。認証付きの実サーバー二者対戦、モバイル実機の性能、本番・ステージングへのデプロイは実施していない。画像とログの成功を、それらの完了として扱わない。

次に品質を上げる場合は、人物の専用クリップと登場時の身体の所作を作り、現行のカットインと差し替える。今回の静止絵を使った動きは完成キャラクターアニメーションの納品ではない。

サーバー設計の参照: [Cloudflare Alarms](https://developers.cloudflare.com/durable-objects/api/alarms/)。準備期限を既存の一つのalarmスケジュールに統合し、重複呼び出しで開始時刻を再設定しない。

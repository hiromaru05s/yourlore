# 勝敗01「圧壊の王冠」の本体適用

承認された `2026-09-29-shatter-five` の01を採用。勝利時は相手の紋章、敗北時は自分の紋章を同じ破断・重力・接地モデルで砕く。全画面の本の演出を置き換え、盤面を見せたまま5.4秒で決着し、既存の結果・再戦・ホーム・ログ確認へつなぐ。

## 適用と根拠

| 項目 | 対応 | 検証 |
|---|---|---|
| 承認01の動き | crownRenderer.tsへ01だけ抽出。元の面・亀裂・時間・乱数・物理を維持 | 同一素材・矩形で14時点の画素が承認rendererと完全一致 |
| 絵・枠・HP・シールド・雫の一体性 | outcomeSurface.tsが実DOM座標・CSS画像・現在の肖像canvas・数字・フォントを一枚に合成 | 両視点で3つの元DOM部品を一括非表示、完了時復元 |
| 資源配置③との統合 | mainの0fac254 / dca4fc6を取り込み | CSSを書き戻さず、実際の修正済み配置から合成 |
| 数値の正確性 | プレビュー固定値を本体へ持ち込まない。終局時の表示値をそのまま砕く | HP0の終局と、HP32のままの降参を別々に確認。シールド6・雫4を変えない |
| 結果画面の順序 | 終局待ち状態を設け、切断通知のshowWinが再生途中へ割り込まない | earlyResultを再生前と再生中に呼び、結果モーダルの先出しがない |
| 両視点の整合 | 敗者の座標を選ぶだけで同じrendererを使用 | you=0/1で相手敗北、自分敗北を確認 |
| 画面端 | 破片の着地点が下端に収まるよう、飛行中に合成面全体の投影位置を補正 | 下端2行に不透明な破片が残らない。PC・390pxの実画像 |
| 中断と解放 | 1つのAbortSignalで読み込み・再生・タイマー・DOMを所有 | 準備中中止、スキップ、destroy、非表示、置換、リサイズ、低減モーション |
| 読み込み負荷 | 演出コードを終局時に遅延ロード。未採用4案を製品へ含めない | typecheck / build |

低減モーションは短い静的な勝敗表示。再接続で既に終局している盤面・引き分けは既存の結果画面へ進む。試作と異なり、実対戦では最終ダメージ表示が済んでから始まるため、演出内でHPを仮の32→0へ書き換えない。

## 見た目と機能検証

承認元を `approved-renderer.ts` / `approved-crown-pair.mp4` とハッシュに保存。実盤面で両視点の通常再生を録画し、溜め・破断・着地の画像を比較した。表面・縁・数字が同じ破片へ残ること、資源③の下がった配置と下端の着地が成立することを確認した。品質参照は銀紋の流墨と承認された01。機能テストの合格をAAA品質の客観的証明とは扱わない。

- `browser-report.json`: 本体と同じBaseControllerの終局処理、動きの承認元一致、ライフサイクル。
- `typecheck.log` / `build.log`: clientとserverの型検証、製品ビルド。
- `tests/crown-outcome-staging.mjs`: 配信資産のハッシュ、公開版BOTの降参操作から敗北演出→結果、両視点の公開renderer・数値維持を確認する。API/accountはfixtureで、認証済みオンライン実対戦の証明ではない。
- `client/outcome-lab.html`: 開発用。製品ビルドの入口には含まれない。

本番ではなく `test.yourlore.xyz` への公開が今回の範囲。公開証跡は `staging/` に追記する。

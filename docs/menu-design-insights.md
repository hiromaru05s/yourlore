# LORE メニュー画面の設計インサイト

更新: 2026-09-29。HOME・デッキ・カード・ランキング・フレンド・ショップ・遊び方など、**対戦画面以外**を対象とする。他のエージェントがメニューを制作・改修するときの共有資料。

## 確定したこと

ユーザーは下ナビ第3稿の **01「静かな光の水平線」** を採用した。単色の小さなアイコン、薄い水平線、選択位置だけを示す光の面、背景を見せる余白が基準。以前の第1稿・第2稿、03の他の4案は承認された仕様ではない。

- 世界観の正典: [world-bible.md](world-bible.md)
- 動きの最低品質: [animation-quality-benchmark.md](animation-quality-benchmark.md)
- 採用実装: `client/src/ui/lounge.ts`、`loungeNavGlyphs.ts`、`loungeNavMotion.ts`、`client/src/styles/loungeHorizon.css`
- 元の比較研究: [第3稿](ui-rework/2026-09-29-home-nav-five/round-3/RESEARCH.md)
- 採用画像: [01 / PC](ui-rework/2026-09-29-home-nav-five/round-3/design-1-desktop.png)

下ナビの承認は、全画面を細線・単色だけにする指示ではない。画面ごとの主役を明確にし、下位の操作を落ち着かせるという判断を他の領域へ展開する。

## 失敗から分かったこと

最初の案は、整ったWebのナビとして見え、ゲームの場との関係が弱かった。次の案は、各項目をメダル・旗・装甲として飾ったが、ユーザーには「ゲームっぽいがダサい」と評価された。

原因の解釈: 同じ強さの輪郭、銀の縁、グラデーション、発光を全項目へ配り、何が重要かを造形で示せなくなった。大きい紋章や背景のキャラクターと、小さな移動先のボタンが競っていた。これはユーザーの言葉そのものではなく、画面と反応からの設計上の分析である。

**「装飾が多い＝ゲームらしい」ではない。** 良いゲームのUIは、世界に入る空気、操作の即時性、情報の序列を一つの構図で扱っている。

## 再利用する判断基準

### 1. 一画面の主役を先に決める

HOMEの主役はシーカーのいる場と、次のデュエルへ進む行動。シャード、設定、移動先は補助情報。ランキングでは現在地と順位、デッキでは構成カード、ショップでは装着時の見え方が主役になる。主役の大きさ・明度・位置を決めてから、周囲の操作を置く。

### 2. 枠ではなく、配置・余白・文字で分ける

「パネルの中のパネルの中のボタン」を増やさない。余白や細い区切りだけで理解できる領域は囲わない。背景上で読む文字には必要な暗い面を用意し、縁取り文字や全面グローで可読性を補おうとしない。

### 3. 選択状態にだけ強い表現を割り当てる

通常・ホバー・フォーカス・現在地を区別する。下ナビ01では通常は灰青、現在地は白、動く光の面と小さな菱形が位置を示す。色だけに依存せず、面・線・位置でも分かる。キーボードのフォーカスは現在地とは別の表示を持つ。

### 4. アイコンは家族にする

同じ線幅、見かけの大きさ、余白、視覚的な重さを揃える。小さなナビに細密な金色の絵を縮小すると輪郭が潰れる。象徴を残して単純化し、ラベルと組み合わせて意味を担保する。大きな対戦紋章と小さなナビに同じ密度を要求しない。

### 5. 動きは状態変化の説明にする

下ナビでは確認済みの画面遷移に合わせて光の面を360msで移し、文字は300ms・5pxで落ち着く。画面遷移を待たせない。保存確認でキャンセルされた場合、行き先を先に選択済み表示しない。

装飾の無限ループを増やさない。再描画・言語変更・ユーザー情報更新で毎回入場演出を再生しない。途中の遷移、画面破棄、サイズ変更でアニメーションと監視を解放する。低減モーション時も選択状態を即時に伝える。

### 6. 同じ枠を全画面へコピーしない

共通なのは色の役割、タイプスケール、間隔、状態表現、動きの速度感。カード閲覧、対戦開始、友人一覧、装飾選択では必要な密度と構造が違う。ページの目的に応じた構成を使いながら共通ナビでつなぐ。

### 7. スマホはPCを縮小した画面にしない

操作対象の高さを保ち、補助文字や余白を段階的に減らす。ラベルの長いランキング等に必要な幅を与える。320px、390px、横向きも実寸で確認する。装飾線と文字の接触、背景の顔への被り、下端の安全域を確認する。

## 次の画面を作るときの手順

1. 現在の画面と実際の導線を読む。別エージェントの改修を確認する。
2. その画面で最も大切な「見るもの」と「行動」を一つずつ書く。
3. 階層・構図が異なる5案を作る。色や角丸だけ違う案を5案として数えない。
4. 採用済み下ナビと、実際のキャラクター／カード絵を入れた状態で比較する。
5. 通常、選択、ホバー、キーボード、長い名前、空状態、PC／スマホを確認する。
6. 動きは通常速度・スロー・反復・途中切り替えを確認する。静止画だけで合格としない。
7. 機能確認、見た目の判断、ユーザー承認、ローカル試作、ステージング反映を分けて報告する。

## 追加で採用されたメニュー構成（2026-09-29）

15案の比較後、ユーザーが **A03・B02・C01** を選択し、ステージング反映を指示した。

- A03「センターマーク」: ロゴを画面中央、プロフィール左、シャードとメニュー右。共通ヘッダーに適用。
- B02「小さなアチューン」: 上からモード選択・対戦紋章・現在ランク・使用デッキ。選択タブだけでは開始せず、中央の紋章から選択したモードを開始する。
- C01「一枚の情報面」: ランキングとショップを一面に整理。PCは一覧＋補助情報、スマホは補助情報を一覧の上へ。デッキ構築・カード図鑑の専用構成は保持。
- ショップはスリーブとデッキ置き場・墓地の全カテゴリ、所持状態、実際の購入APIと価格を維持。プレビュー選択と装備済みを混同しない。

採用スタイル: `client/src/styles/loungeSelectedMenu.css`。画面実装: `lounge.ts`、`home.ts`、`leaderboard.ts`、`shop.ts`。他の案は引き続き未承認。公開範囲と証拠は [採用記録](ui-rework/2026-09-29-menu-selected/README.md) を参照。

## デッキ・カード・BOTの採用更新（2026-10-02）

ユーザーは、デッキ「手札ファースト」のロック案③「蒼銀の刻印」、カード「ワイド・コレクション」、BOT「チャレンジカード」を選択し、既存ローカル作業との統合・commit/push/mainマージ・ステージング反映を指示した。

- デッキは既存のカードフレームのまま、固定アチューンを9枚の手札の左端に置く。外へ分離しない。固定表示はカード下の蒼銀の刻印と細い鍵。確定操作は薄い水平線の「デッキを確定」。
- 自由枠8枚が満杯でも候補を選び、手札をタップして交換できる。取り外し・追加・直前の操作を戻す機能を持つ。
- カード一覧は密度を維持し、対戦中と同じzoomCardを呼ぶ。一覧専用の詳細画面を増やさない。
- BOTは四つのチャレンジカードで難易度を選び、独立した開始ボタンから開始する。
- 小さい画面では手札を3列、BOTを2列へ並べ替える。採用済み下ナビを維持する。

実装と検証の記録: [採用メニュー](ui-rework/2026-10-02-approved-menu/README.md)。比較用ラボを保存したことは、未選択の効果を製品へ採用したことを意味しない。

## 空間配分の更新（2026-10-02）

ユーザー指示により、デッキ／カードのページ大見出しを画面から外し、ナビで現在地を伝える。デッキ枠の切替は左の縦バーへ移し、手札領域を少し縮め、その他の操作を圧縮してスターター候補を最低2段表示する。カード一覧はPCで検索・種別を1段に集約。フレンドは大きなパネルの入れ子を廃し、一覧と申請欄を薄い区切りで統一する。実装: menuWorkspace.css。検証: [空間配分の記録](ui-rework/2026-10-02-menu-density/README.md)。

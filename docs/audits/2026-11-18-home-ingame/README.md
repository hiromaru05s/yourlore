## 検証

- 修正前の本番用テスト280本はすべて成功したが、上記の操作順序・遅延条件を追加すると不具合を再現できた。既存テストの成功だけで安全とは判断しない。
- 全433カードの両側866ケース、200試合・34,192遷移を追加監査。全試合決着、例外・反復停止・タイムアウト救済ゼロ。これは設定した盤面・シードの検証であり、全組合せを網羅するものではない。
- HOME / カード / ランキング / フレンド / ショップ / 遊び方を1440×900、1280×720、960×640、844×390、667×375で確認。計30組。ページ例外・HTTPエラー・横方向のページはみ出しなし。
- デッキ名変更・Escape・保存の永続化・離脱時のダイアログ破棄、日本語 / 英語 / 韓国語切替、スターター購入と残高更新をブラウザ確認。
- ローカルの実Worker・D1・WebSocketで2アカウントの通常戦・ランク戦。マッチング、ランク戦市場確認、初手交換、ターン終了、再読み込みで同一部屋・同一ターンへ復帰、相手降参、決着表示、再開情報の消去、HOME復帰を確認。ランク戦のMMR精算もAPIで確認。
- 再実行用の実通信テスト: `tests/local-duel-lifecycle-browser.mjs`。`PLAYWRIGHT_MODULE`、`LORE_TEST_USERS`（ローカル用cookieを持つ2アカウントJSON）、`LORE_TEST_ORIGIN`、`LORE_TEST_OUTPUT`を指定。ランク戦は `LORE_TEST_RANKED=1`。実アカウントの秘密情報はリポジトリへ保存しない。

- 初期のオンボーディング500は、ローカルSQLiteテストアダプタがD1 batch内のSELECTを実装していなかったため。本番の不具合として計上せず、テストアダプタを修正。

- ブラウザ確認はChromeのPC / 小型横画面。実機Safari・iOS・Androidの全機種や、本番ユーザー同士の実対戦は未確認。表示の確認とルール・通信テストの成功は別々に評価した。
- 依存関係は互換範囲の更新で既知の指摘を7件から4件へ削減。残りはビルド用picomatchのReDoS（GHSA-fc5q-39xc-vjpf）とその依存元。検証時の公開最新版4.0.7も対象で修正版未公開。ゲームの入力をこのglob処理に渡す経路は確認していないが、npm auditが完全にゼロになったとは報告しない。

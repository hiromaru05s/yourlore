## 6方向

| 案 | 主形状・素材 | 動作 |
| --- | --- | --- |
| 01 金綴じの帳簿 | 湾曲した紙面、重なる薄い頁、金箔の勘定線 | 背を起点に頁が持ち上がり、重なりを保って閉じる |
| 02 鋳金の契り | 絵柄を保持した12区画の金属レリーフ | 時間差で丸く打ち出され、側面を見せ、鋳戻る |
| 03 絹札の荷解き | 3本の絹帯、織り目、細い縁 | 縦方向の波が位相をずらして通り、張力が抜ける |
| 04 天秤の商約 | 左右の秤皿状の絵柄、中央軸、細い吊り線 | 支点の周囲で重さが釣り合い、左右が定着する |
| 05 金庫の解錠 | 厚い象嵌扉、蝶番、金属枠 | 外側を支点に二枚の扉が開き、時間差で閉じる |
| 06 夜市の開帳 | 天幕、襞、細い金縁 | 上部が張り出し、側幕が引かれ、折り目が戻る |

見習い商人は銅と紙、控えめな変形。王都の商売人は金属反射と彫金を強める。闇商人は黒い素材と紫銀の内面にし、変形量も変更。方向間の差は色替えだけでなく、幾何形状・支点・軌道・位相に持たせた。

## 自己レビューで直した点

- 最初の帳簿は単なる湾曲に見えたため、薄い頁の重なりを追加。
- 天秤の支点が読めなかったため、同じ絵柄に接続した軸と吊り線を追加。
- 金庫の初稿は9枚の分割板にしか見えなかったため、蝶番を支点にした二枚の扉へ変更。
- コスト・能力値がカード外側へ張り出すため、カード面の余白込みで capture する形へ修正。余白の透明領域から不要な側面が伸びないよう、側面にも alpha mask を適用。
- コイン周りの輪が独立した装飾に見えたため撤去。材質の厚みと絵柄の変形に絞った。
- 開始・終了で材質の色が変わらないよう、通常カード色から反射材質へ連続移行し、最終状態で元の色に戻す。

## 検証と限界

- `tsc -p client/src/dev/merchant-six/tsconfig.json --noEmit`: 成功。
- 専用 Vite entry の build: 成功。Three.js を含む共有描画チャンクに500 kB超の警告あり。比較用 bundle であり通常プレイの bundle への追加ではない。
- `verify.mjs`: 18個の途中時刻/終端ケース、36個の実盤面ケース（3種×6案×両陣営）、終了・低減モーションの2ケース、合計56記録。3枚同時、カード復元、iframe破棄、320/390px、白/暗背景、WebGL描画を検証。`qa/report.json`。
- `record.mjs`: 6案を同じ時刻で合成した30fps比較動画（3種、11.4秒）。これは決定論的な連続フレーム動画で、実機のフレームレート測定の代用ではない。
- 実再生の frame interval と再生前後の GPU resource count は `qa/performance.json`。比較1画面あたり WebGL context は1。3枚の表面 texture と3枚の alpha mask をキャッシュし、反復中に geometry/texture/program 数は増えない。
- ブラウザ描画・画面内での形状差・通常再生のタイミングを自己確認した。**機能成功とユーザーの見た目の承認は別**。この成果物は6案の比較であり、原神相当・承認済み最低基準への到達をテスト結果だけで断定しない。
- 実盤面は実際の GameView / boardProjection を使う固定 fixture。自然なBOT操作、認証済みオンライン対戦、Windows機での性能、ステージングでの配信確認を行ったものではない。
- 闇商人の使用位置は選定用。実際の購入画面への遷移・ゲーム状態の更新・終了後の虚無処理は採用時に既存所有者へ接続する必要がある。

検証スクリプトは `PLAYWRIGHT_MODULE` で Playwright の配置を指定可能。比較動画 `qa/comparison.mp4`、3種の一覧 `qa/*-six.png`、拡大 `qa/variant-*.png`、盤面・スマホ画像を保存。

## 前稿の問題と変更

前稿 `Renderer.bead()` は楕円を塗り、固定の弧で白い反射を描いていた。表面の曲率と背景の屈折が結びつかず、暗い緑の玉に見えることがあった。第2稿では厚みのある暗黙曲面を描き、前後の境界と法線から反射・透過方向を求める。

- 立体の主形状: 楕円体と滑らかな結合。5案で首・尾・液柱・接触面を変える。
- 透過: 屈折率1.333を制作値に使い、背景画像の参照位置を変化させる。単に透明度を下げない。
- 反射: 法線と視線角によるFresnel、面光源風の環境の映り込み、狭いハイライト。
- 厚み: 背面までの経路に応じた色の吸収。L4のみ少し強くし、他案は澄んだ水を維持。
- 運動: 共通時計で液面そのものを変形。流体力学の厳密解・実測水滴の再現ではなく、設計した形状アニメーション。
- アイコン: 元の `dew-ui.webp` を保持。飛行中の液体は一切このアイコンを素材にしない。

## 見比べ方

- 質感を拡大: 共通背景の文字や線を透かし、材質の違いを比較。
- 付与フロー: カード面で成立 → 移動 → 既存の雫へ吸収。数値は2190msで一度だけ5→8。
- 実盤面: 現行GameViewのローカルfixture、実矩形を使った飛行と到着。オンライン対戦ではない。
- 旧表現と比較、白／暗、速度1 / 0.5 / 0.25、任意時刻、両陣営、両側同時、低減モーション。

屈折はスクリーン空間の近似。拡大／付与フローは描画した背景そのものをサンプルする。実盤面は近傍の肖像Canvas、カードアート、雫画像、盤面色から背景を再構成するため、DOMの全ピクセルを正確に屈折させるものではない。この制約はプレビュー内にも表示。

WebGL非対応では新材質を再現できない旨を表示。別の簡易表現を同等品質として扱わない。中断・ページ終了は元の数値へ戻し、Canvas／texture／buffer／programを解放。

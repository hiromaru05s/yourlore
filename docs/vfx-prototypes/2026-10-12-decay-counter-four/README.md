## 既存実装の調査

調査基準は取得した `gh/main` の `f5531ec3`。Desktopの作業中mainは古いため、独立worktreeをこの統合版から作成した。

- `client/src/shared/engine.ts:addDecay` は `decayCnt` を増やす。閾値未満で専用の付与イベントは発行していない。
- `client/src/ui/cardView.ts` は `腐敗 n/3` の状態表示を作る。これ自体に付与専用アニメーションはない。
- `client/src/ui/statusGrant/runtime.ts` はシールド／烙印用で、腐敗カウンターには接続されていない。
- 3個以上で実際に破壊された場合は `destroy.cause='decay'` により、既存の `ui/decay/` の溶解へ分岐する。
- `dev/series-vfx-d/` には腐敗関連の試作がある。それを通常対戦へ採用済みとは扱わない。

今回の4案は「受ける腐敗カウンター」の付与用。「腐敗」パッシブ能力の付与や、3個による破壊とは別の意味を持つ。

## 制作前に確認したフィードバック

メモリに記録された承認・却下理由に加え、2026-10-12「吸血鬼召喚エフェクト6種を制作」の直近ユーザー発言を読み直した。

- 「基本的に１パターンを使い回した６パターン」→4つの異なる表面形状関数を制作。色や速度だけを変える案にしない。
- 「なんかのマークかな？ってなっちゃう」→抽象的な紋章を避け、菌糸・濡れた膜・錆・めくれた皮膜を形と反射で区別する。
- カード面・物質・動きの分離、突然の別物体、二重発火→nativeカードを維持し、各カードにsurfaceを1枚だけ設置する。付与の1回分を共通時計で描画する。
- 腐敗破壊で「雫が落ちる効果いらない」と絞られた経緯→付与にも落下する雫、盤面の毒溜まり、後続の飛行物を足さない。
- 「機能テスト成功」と「見た目が承認基準を満たす」は別→連続再生・途中フレーム・実盤面を残し、承認は未選定と明記する。

## リサーチと今回の設計判断

### 一次資料

1. [Blizzard: Developer Insights — The Art Behind THE SCIENCE](https://news.blizzard.com/en-us/article/22552047/developer-insights-the-art-behind-the-science)。Effects Artist本人による制作解説を読んだ。Magneticの説明からは、付着先を明確にする大きく直接的な形の重要性を採用。Kangorの説明からは、主動作を中心に二次動作を足す順序を採用。カウンター付与は頻出なので、画面全体に及ぶ大技の重さを持たせない。
2. [Riot: Visual Effects](https://www.riotgames.com/en/artedu/visual-effects) および [Portfolio and Reel Suggestions / VFX](https://www.riotgames.com/en/portfolio-and-reel-suggestions)。資料本文の形・明度・色・時間設計、ゲーム情報を主読みにする方針を確認。4案の意味を「付与された対象と増えた数」に集約し、対象の外へ広げない。
3. [GDC 2017: Artistic Principles of VFX](https://gdcvault.com/play/1023943/Visual-Effects-Bootcamp-Artistic-Principles)。Blizzard／Riot登壇の講演概要を確認。講演動画全編を視聴した、内部シェーダーを分析したという主張はしない。
4. [Riot: Animation in the League of Legends Client](https://www.riotgames.com/en/news/animation-league-legends-client)。Web上の演出構成と描画負荷の解説を確認。本作ではタイムラインを共有し、停止中の継続描画を止め、描画コンテキストを案ごとに増やさない。

旧Riot VFX Style GuideのURLは現在ホームへリダイレクトするため、PDF全体を取得済みとは扱わない。他作品の絵・素材は配布物へ使用していない。

## 実装と範囲

- `client/src/dev/decay-counter-four/` のみに演出と選定画面を配置。
- 材質は専用の手続き的surface。ノイズだけで覆わず、分岐・粘性面・結晶境界・折れた皮膜の主形状を個別に定義。
- nativeカードを消さずに子canvasを付ける。既存カードの変形・盤面投影を継承し、別座標のゴーストを作らない。名前・数値・状態バッジは上に維持する。
- メイン画面は4案で1個のWebGLコンテキスト。盤面fixtureは1個。低減モーション／WebGL使用不可ではnativeカウンターを更新する。
- カウンターは試作画面内の表示用。同期エンジンの権威的状態を遅延させる処理は追加していない。
- 通常速度、低速、反復、静止シーク、中断、リサイズ、タブ非表示、pagehideを扱う。

## 検証

検証スクリプトは `check.mjs`。実行結果と連続録画は `qa/` に保存。型検査・ビルド・ブラウザ機能検証の結果と、途中フレームの目視評価は区別する。

- 最終のブラウザ機能検証は62項目成功。カウンターの切替時刻、両陣営×4案×単体／3体、終了後の透明ピクセル、低減モーション、キャンセル、反復、320／390／844／1440pxを確認。ブラウザ例外は0。
- 対象ソースのTypeScript検査成功。通常対戦への変更はないため、ゲームのルール全体を再テストしたという主張はしない。
- Vite production build成功（283 modules）。比較ページが実盤面モジュールを含むためchunk-size warningは出るが、build errorはない。
- 最終の4案同時再生はローカルHeadless Chromeで98フレーム、フレーム間隔p50=16.7ms、p95=16.8ms。録画負荷や並行作業の影響を含むローカル観測であり、物理スマホの60fps保証ではない。
- 一つのatlasへまとめて描画してから各カードへコピーする。タイルは256×320、ノイズは三角関数を使わないhash、バッジ文字は変化時だけ更新する。4案の構造を維持して読み戻しと計算を減らした。
- 目視では、主形状4種の差、元のカード絵を残した表面変化、盤面への追従、狭い範囲への収束を確認した。商用タイトルと同等という認定やユーザーの採用判断は行っていない。

保存した[連続再生](qa/continuous.mp4)は同じ最終surface rendererを使った実時間描画。カードはnative表示をキャプチャし、録画内のカウンター文字だけを比較用canvasで再描画している。実盤面の状態バッジは引き続きnative DOMを使用する。`continuous-frames.jpg` はその録画から8fpsで抜いた連続フレーム。録画エンコーダーのフレームレートと上記のブラウザrAF計測は異なる指標として扱う。

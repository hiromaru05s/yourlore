# 腐敗カウンター付与 — 4案

2026-10-12 / 第2稿。選定用ローカルプレビュー。通常対戦の演出選択・エンジン・controller・公開環境は変更しない。

## 開く

```sh
node node_modules/vite/bin/vite.js --config client/src/dev/decay-counter-four/vite.config.mjs
```

[4案比較](http://127.0.0.1:55264/decay-counter-four.html)。4案の同時再生、1案の拡大、実盤面、両陣営、3体同時、白／暗背景、0.5／0.25倍、シーク、中断、モーション低減を備える。0→1、1→2、一度の0→2を比較できる。

## 第2稿での作り直し

初稿はユーザーから「部分的に演出されるのが不自然」「他のアニメーション品質と近いものを」と却下された。初稿の局所的な形状を拡大するだけではなく、描画方式を変更した。

- 実カードの絵柄と枠を `captureCardSurface` で取得し、色・輪郭・明暗差を演出の入力へ変更。名前・数値・状態表示はnative DOMを維持。
- 小さな根／膜／錆／皮を上に貼る形状を廃止。4案ともカード全面を覆う進行面と、元の絵柄を残す材質変化を制作。
- ①周縁から入り内側へ収束、②上から濡れ広がり下へ排出、③全面の鉱物化と面ごとの復元、④下から広がる皺と折り目の解放。入口と終わり方も区別。
- 輪郭の反射、絵柄の明暗を拾う細光、主形状の陰影、狭い反射を同じUV上で描画。
- 約1.2秒だった初稿から約2.0–2.3秒へ時間配分を改め、侵入・全面変質・収束の間を読ませる。
- 初稿の証跡は `qa/` に履歴として保持。**現行の証跡は `qa-v2/`**。初稿の成功テストや動画を改訂版の証拠として使わない。

承認済み「銀紋の流墨」の動画から抽出した連続フレーム、800ms／1500msの原寸画像、現行 `riftInkMaterial.ts` と腐敗破壊 `decay/fixed-face.ts` を再確認。共通点は「元の絵柄・枠の詳細が変質中も関係を持つ」こと。除外・破壊のようにカードを消失させる動作は、カウンター付与へ流用していない。

## 既存実装の調査

調査基準は取得した `gh/main` の `f5531ec3`。Desktopの作業中mainは古いため、独立worktreeをこの統合版から作成した。

- `client/src/shared/engine.ts:addDecay` は `decayCnt` を増やす。閾値未満で専用の付与イベントは発行していない。
- `client/src/ui/cardView.ts` は `腐敗 n/3` の状態表示を作る。これ自体に付与専用アニメーションはない。
- `client/src/ui/statusGrant/runtime.ts` はシールド／烙印用で、腐敗カウンターには接続されていない。
- 3個以上で実際に破壊された場合は `destroy.cause='decay'` により、既存の `ui/decay/` の溶解へ分岐する。
- `dev/series-vfx-d/` には腐敗関連の試作がある。それを通常対戦へ採用済みとは扱わない。

今回の4案は「受ける腐敗カウンター」の付与用。「腐敗」パッシブ能力の付与や、3個による破壊とは別の意味を持つ。

## 制作前に確認したフィードバック

メモリに記録された承認・却下理由に加え、2026-10-12「吸血鬼召喚エフェクト6種を制作」の直近ユーザー発言を読み直した。

- 「基本的に１パターンを使い回した６パターン」→4つの異なる表面形状関数を制作。色や速度だけを変える案にしない。
- 「なんかのマークかな？ってなっちゃう」→抽象的な紋章を避け、菌糸・濡れた膜・錆・めくれた皮膜を形と反射で区別する。
- カード面・物質・動きの分離、突然の別物体、二重発火→nativeカードを維持し、各カードにsurfaceを1枚だけ設置する。付与の1回分を共通時計で描画する。
- 腐敗破壊で「雫が落ちる効果いらない」と絞られた経緯→付与にも落下する雫、盤面の毒溜まり、後続の飛行物を足さない。
- 「機能テスト成功」と「見た目が承認基準を満たす」は別→連続再生・途中フレーム・実盤面を残し、承認は未選定と明記する。

## リサーチと今回の設計判断

### 一次資料

1. [Blizzard: Developer Insights — The Art Behind THE SCIENCE](https://news.blizzard.com/en-us/article/22552047/developer-insights-the-art-behind-the-science)。Effects Artist本人による制作解説を読んだ。Magneticの説明からは、付着先を明確にする大きく直接的な形の重要性を採用。Kangorの説明からは、主動作を中心に二次動作を足す順序を採用。カウンター付与は頻出なので、画面全体に及ぶ大技の重さを持たせない。
2. [Riot: Visual Effects](https://www.riotgames.com/en/artedu/visual-effects) および [Portfolio and Reel Suggestions / VFX](https://www.riotgames.com/en/portfolio-and-reel-suggestions)。資料本文の形・明度・色・時間設計、ゲーム情報を主読みにする方針を確認。4案の意味を「付与された対象と増えた数」に集約し、対象の外へ広げない。
3. [GDC 2017: Artistic Principles of VFX](https://gdcvault.com/play/1023943/Visual-Effects-Bootcamp-Artistic-Principles)。Blizzard／Riot登壇の講演概要を確認。講演動画全編を視聴した、内部シェーダーを分析したという主張はしない。
4. [Riot: Animation in the League of Legends Client](https://www.riotgames.com/en/news/animation-league-legends-client)。Web上の演出構成と描画負荷の解説を確認。本作ではタイムラインを共有し、停止中の継続描画を止め、描画コンテキストを案ごとに増やさない。

旧Riot VFX Style GuideのURLは現在ホームへリダイレクトするため、PDF全体を取得済みとは扱わない。他作品の絵・素材は配布物へ使用していない。

## 実装と範囲

- 変更は `client/src/dev/decay-counter-four/` と専用HTML、比較資料のみ。
- 各カードのフレームと絵柄を既存キャプチャ関数で取得。キャプチャ用の複製は画面外で一時的に使用し、完了時に削除。コスト・名前・ATK・HP・状態は複製せず、元のDOMを最前面に維持。
- 表面canvasはnativeカードの子要素。盤面の投影を継承し、対象と別座標で浮かない。
- 実カードの色／透過輪郭／明暗勾配、4種の材質、陰影、反射、収束を共通時計で描画。
- 4案で1個のWebGLコンテキスト、盤面fixtureで1個。320×500のタイルをatlasへ一括描画。GPU上のカード画像キャッシュは12枚を上限とする。
- カードを非表示にしない。モーション低減／WebGL使用不可ではカウンター更新を維持する。
- 通常速度、低速、反復、静止シーク、中断、リサイズ、タブ非表示、pagehideを扱う。

## 検証

`check.mjs` の出力は `qa-v2/verification.json`。改訂版では69項目成功、ブラウザ例外0。

- ピーク1100msでカードを9領域に分割し、元の絵柄との画素差を確認。全4案・全9領域で変化画素が65%以上あることを検証（実測最小85.1%）。これは局所パッチへ戻る回帰を捉えるチェックであり、見た目の合否判定ではない。
- カウンター0→1、1→2、0→2の切替時刻、両陣営×4案×単体／3体、終了後の透明画素、モーション低減、中断、連続再生、320／390／844／1440pxを確認。
- 比較欄を隠した実盤面モードでカード種を変更しても、再表示後に正しい絵柄を使用することを3種類で確認。
- ローカルHeadless Chromeの4案同時再生で158フレーム。p50=16.7ms、p95=16.8ms、最大16.8ms。物理スマホや本番の性能保証ではない。
- 型検査・production buildとも成功。実盤面モジュールを含むため500kB超のchunk警告が出る。記録は `qa-v2/typecheck.txt`、`qa-v2/build.log`。
- `record.mjs` は実際の比較ページを通常速度で録画する。nativeカード・実カウンターDOM・演出canvasをそのまま収録し、別の比較用レンダラーや手描きのカウンターへ置換しない。

機能検証成功と見た目の評価は別。通常速度の連続フレーム、低速の途中状態、白／暗背景、実盤面、モバイル幅を目視して、全面の変質と4種の進行・復元の差を確認した。ユーザーの見た目承認は未取得。

通常対戦への接続、3個目から既存破壊演出への連結、効果音、物理スマホ、認証オンライン対戦、ステージング・本番公開は、この選定プレビューに含めない。

## 一次資料の調査

1. [Riot Games / Visual Effects](https://www.riotgames.com/en/artedu/visual-effects)。教材本文を確認。VFXはゲーム状態の伝達と魅力を両立し、発生源・キャラクターとの対応を保つ。今回: 判定前の構えに絞り、ダメージ・成功・シールド値増加に見える数値や確定表示を足さない。
2. [GDC 2017 / Artistic Principles of VFX](https://media.gdcvault.com/gdc2017/Presentations/Chamberlin_Keyser_ArtisticPrinciplesVFX.pdf)、Jason Keyser / Hadidjah Chamberlin。PDFを取得して全テキストを読み、38ページのコントラストと焦点の図版をレンダリングして確認。形、焦点、色の役割、緩急、予備動作と二次動作を参照。今回: 1秒内で主動作を一回だけ行い、広い面と細い縁を分ける。
3. [Blizzard / Animated Shield](https://hearthstone.blizzard.com/en-us/cards/39308-animated-shield/)。公式カードの挑発モチーフを確認。今回: 盾として認識できる先端・厚み・左右の連結。素材やアニメーションはコピーしない。
4. [Riot Games / Galio](https://www.leagueoflegends.com/en-us/champions/galio/)。公式キャラクター・能力名と守護者の文脈を確認。今回: 踏み込みと重い構えをカード自身へ翻案。能力動画のタイミングを計測したという主張はしない。

旧Riot VFX Style Guide URLはホームへリダイレクトしたため、閲覧できた資料としては扱わない。1000ms、各ピーク時刻と材質はLORE用の独自設計値。

## 4つの構造

| 案 | 主形状・素材 | 発生と動き | 収束 |
|---|---|---|---|
| 01 双翼の大盾 | 厚みのある鋼製の左右板、縁金、鋲 | 左右の上枠から起き、盾の稜線へ噛み合う | 左右の同じ上枠へ折り戻る |
| 02 不退の踏み込み | 元のカード面、角金、前縁の圧 | 引く→一度前進→平らな面で接地 | 元の位置へ落ち着く |
| 03 戦旗の翻り | 1枚の変形メッシュ、織り目、縁刺繍 | 上枠から布が持ち上がり、一度翻る | 裾から上枠へ巻き戻る |
| 04 城郭のせり上がり | 段差のある石材、胸壁、目地 | 左右の枠から順に高さを増し、上辺が閉じる | 同じ石が枠へ沈む |

全案でカードの実アートを使い、カード幅180・高さ270を基準として源を固定。実盤面では `boardMatrix` と実際のDOMカード寸法を使い、WebGLの投影行列へ直接写す。拡大プレビューと同一のモデル・時計を使用。実盤面ではDOMカードと全パッシブ表示を維持し、同じ時計でカード自体を動かす。WebGLは立体演出のみを重ねる。

## ダイスとの境界

既存の `engine.ts` は `diceChance` で挑発を判定し、成功した場合にランダムな挑発持ちへ攻撃対象を置換する。失敗も含めて事前演出が必要。既存の `DiceSource` はカードIDと陣営を持ち、同名複数個体のUIDや判定理由を持たない。このため、カードIDだけで本番のダイスを挑発判定と推定しない。

今回の比較フィクスチャは挑発元のUIDを明示して、事前演出を完了してから既存の `diceRollAnim` を呼ぶ。5/2の結果は比較用の固定値で、確率・ゲームルールを変更しない。選定後の接続では専用のreason/UID情報をイベントに持たせること、攻撃アニメーションとの順序を確認することが必要。

「2体同時」は独立するソース2体の描画負荷と復元を確認するストレス条件。通常対戦で2回ダイスを振るという意味ではない。

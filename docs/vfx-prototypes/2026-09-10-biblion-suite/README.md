# Biblion board VFX suite — 2026-09-10

実際の GameView と共通の演出コードを使う、9種類の確認画面。攻撃力は青、モンスター体力は赤。Biblion の象牙色・紺・金、眼と羅針盤、魔導書を共通モチーフにする。演出内に数値ラベルは追加しない。

## 再生

リポジトリ直下で実行:

```sh
npx vite --config docs/vfx-prototypes/2026-09-10-biblion-suite/vite.config.mjs
```

http://127.0.0.1:5198/ を開く。各ボタンで再生、対象プレイヤー切替、ループ、停止、同時発動の確認ができる。

| --- | --- | --- |
| 攻撃力上昇 | 青い上矢印3本、カード外周の細い光 | 同一モンスター UID の実効攻撃力増加 |
| モンスター体力上昇 | 赤い上矢印3本、淡い赤の外周 | 同一 UID の実効最大体力増加。ダメージ回復は除外 |

| 残存魔法発動 | 発動元の上で Biblion の眼が開く | 公開 `enchantActivate` イベントの正確な UID |

## 実装

- `client/src/ui/biblionFx.ts`: 動的 Canvas2D、輪郭・結晶・軌道・手続き生成の砂埃。共通キャンバス1枚、DPR上限2、同時エントリー上限24。発動中だけ描画し、停止・非表示・破棄時に解除。
- `statRiseVisual.ts` / `statRise.ts` / `statRiseChanges.ts`: 既存の Three.js 上矢印を青/赤に拡張。同時の攻撃/体力上昇では赤を600ms遅らせる。盤面上のカード位置・角度・大きさを保持。
- `anim.ts` / `boardMotion.ts` / `sceneMotion.ts`: 既存のカード移動とUIに接続。数値表示・カードの移動先を演出用に変更しない。
- `shared/engine.ts` / `shared/types.ts` / `game/controller.ts`: 残存魔法に公開発動イベントを追加。ゲームルール・バランス値は変更しない。

残存魔法のターン開始処理は、結果イベントを出した場合だけ発火する。反応型は召喚・回復・ダメージ・血の魔法・再発動・ダイス6・除外・破壊無効・再抽選など、実際の解決箇所から発火する。残りターンの減少、対象なしの体力バフ、常時適用のコスト変更や静的な全体補正では再生しない。

描画は `prefers-reduced-motion` と非表示タブを考慮。UI操作・対戦の正規状態が演出キャンバスに依存しない。新規に設置した残存魔法も公開 UID を保持する。

## 検証と記録

- `npm run typecheck`: client/server 成功。
- `npm run build`: 成功。既存の大きいチャンクと duelReadiness の静的/動的インポートに関する警告あり。
- `node tests/biblion-vfx.mjs`: 発動元 UID、カウントダウン/対象なし抑制、召喚反応、体力増加と回復の区別、全描画分岐の有限座標・透明度を検証。
- `node tests/stat-rise.mjs`: 初期表示、同一オブジェクト変更、再描画、両陣営、オーラ、減少、所有者変更、再入場、対戦終了を検証。
- `node tests/quest-quick.mjs`: クエストと10種類のクイックの既存ルールを検証。
- 実ブラウザ: 1280×720 と 390×844 で9種類の再生完了を確認。スマホ幅は相手側9種類、自分側はマナ・召喚も確認。横スクロールなし。停止後のカード残骸なし。同時発動でも共通キャンバス1枚。
- `qa.json`: DOM終了状態とキャプチャ時の記録。`frames` は取得したスクリーンショット枚数であり、ゲームのFPS測定ではない。
- JPG は実際の盤面の途中フレーム。`summon.mp4` はキャプチャ時刻を保持した召喚の録画。モバイル専用の画像も保存。

本確認画面は固定した盤面に実演出を呼び出すもの。ネットワーク越しの両クライアント同期、低性能端末のFPS、全カードの反応組合せは網羅検証していない。既存音声を使用し、新規の音源は作成していない。ハースストーン/シャドウバースは演出の目標であり、同等品質を認定するものではない。

過去の金色攻撃/緑色体力の画像は旧案。このフォルダと共通のランタイムコードが今回の青/赤版。

|---|---|---|

## 制作判断

第2稿の石碑・金属の錠・金の細線が視覚の主役になり、「紫の魔法による封鎖」が読みづらかった。今回は造形・素材・動作を再制作。大きな紫の魔法陣、濃紫の面、薄紫の芯、紫のオーラを主役にする。円だけを浮かべる装飾ではなく、カードの表面模様から外周術式へ発生源をつなぎ、オーラそのものの圧縮・拘束・閉鎖・収束を描く。

- 品質基準 `docs/animation-quality-benchmark.md`、`docs/vfx-art-direction.md` を再読。前回確認した「銀紋の流墨」の表面→主素材→収束の連続性を継続。
- 過去の指摘を再確認。独立物体の突然出現、大粒の装飾、垂直着地、二重発動を避け、面からの連続的な構築と消去を使用。
- 第2稿で調査したRiotの可読性・ノイズ削減原則を継続。紫の意味は普遍的な色彩法則という主張ではなく、今回のユーザー指定と対象カードのオーラに基づく。
- 第2稿は `60749a3b` に保存。スクロール修正 `1eb8c41b` は維持。

## フレームの欠けのみ修正（2026-10-13）

更新プレビュー: http://127.0.0.1:5496/silence-four.html?revision=3-framefix

原因は `surface.ts` がキャプチャの12%余白を切り捨てていたこと。コスト飾りはカード左端から9%、攻撃・体力飾りは左右4%と下端2%はみ出すため、演出中だけ直線で切れていた。

- キャプチャ全体を保持し、描画用の板を同じ余白分だけ拡張。カード本体の2×3寸法・位置・傾きは維持。
- 紫の表面着色も元のカード座標に補正。透明余白は深度を書き込まず、背後の魔法陣を隠さない。
- 4案の形状・動き・時間設計、魔法陣テクスチャ、オーラは変更なし。共通カード実装や通常対戦は変更なし。
- `node tests/silence-four-frame.mjs`: 両カードでテクスチャ外周が透明かつ切り捨てられていた装飾画素が残ることを確認。4案×両カード×両陣営の16ケースで表示と終了復元を確認。390pxで縦スクロール可、横はみ出しなし、JS例外0。
- 修正前後のカード画像、0/800/1800/3000msの比較画面、実盤面画像を目視確認。検証画像とレポートは `qa/frame-fix/`。


## ④「紫淵の封刻」の採用（2026-10-13）

ユーザーの「４でステージング適用して」により、NT_SEAL5 / NT_SEAL3 の召喚へ④を選定。
`ui/silenceSummon` に承認済み描画を移し、比較プレビューも同じモジュールを参照する。
手札・生成召喚の `flyIntoSlot` と直接召喚の `playMonster` に専用経路を追加し、汎用演出を重ねない。
1900msで一度接地、3000msで元カードに復元。フレームの透明余白、紫の魔法陣・オーラ・タイミングを保持。

- `tests/silence-summon.mjs`: ゼロ時刻描画、単一接地、共有GPU、中断、捕捉中の取消、再発動、低減モーション、失敗時復元、資源解放を検証。production suiteに登録。
- `tests/silence-summon-browser.mjs`: 両カード×両陣営×直接/手札/生成の12経路で専用演出・復元を確認。3枚同時の取消、低減モーション、JS例外0。
- 画像・連続録画・結果: `runtime/`。ローカルの実GameViewによる実ランタイム検証であり、認証済みオンライン対戦の証跡ではない。
- ステージング反映の結果はリリース記録に追記する。

並行公開の負荷調整時、初回ブラウザー検証は全12経路・低減・同時取消のレポート保存後、録画の終了待ちで停止。クライアント単独の型検査も中断し、最終判定はクリーンな deploy-guard に委ねる。ブラウザー検証の録画は `RECORD_VIDEO=1` で任意実行。

録画なしでブラウザー12経路・低減・同時取消を再実行し、プロセスの正常終了まで確認済み。

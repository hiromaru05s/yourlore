## 現行経路の調査

「完全に演出がない」わけではない。主チェックアウトとベース `8d7cdbe0` の `client/src/game/controller.ts` は、イベント再生後に前後状態の `guts` を比較し、減少した生存カードへ `A.flashBadge(..., fx.guts, good)` を呼ぶ。`client/src/ui/anim.ts` の `flashBadge` はカード上に文字のピルを置き、1150ms後に削除する。専用のカード表面変化や耐久動作はない。

`engine.ts` には通常攻撃、反撃、味方への攻撃等の気合消費経路がある。卵の `dur`、気合の獲得・補充、`MIND_BURST` の全消費とは区別する。今回の比較は「致命傷を気合1個で耐え、体力1で生存する」瞬間だけを対象にした。表示する攻撃者も対象の体力を上回る攻撃力に設定した。

採用時には、単なる前後差分だけでは「耐久」と「能力コストとしての全消費」を区別できない点を解決する必要がある。命中に同期した耐久イベントへつなぎ、既存の文字バッジと二重に再生しない。今回、そのランタイム変更は行っていない。

## 着手前の調査と制作判断

参照日：2026-10-12。

1. `docs/animation-quality-benchmark.md`、`docs/vfx-art-direction.md`、`docs/world-bible.md` を読んだ。主チェックアウトに保持される承認済み `inscription.mp4` から5fpsの連続フレーム一覧を抽出し、発光→表面模様の変形→細い軌跡への収束を確認。今回は、カードの表面・材質・共通時計・消失の連続性を翻案した。紫色や渦を流用する判断はしていない。
2. [Riot Games: Visual Effects](https://www.riotgames.com/en/artedu/visual-effects)。発生源との一貫性とゲームプレイの可読性を両立する説明を参照。今回の適用：明るい線を細く限定し、粒子の量や全画面光で強さを代用しない。カードの数値・パッシブは最前面に残す。
3. [Hearthstone: The Art Behind THE SCIENCE](https://hearthstone.blizzard.com/en-us/news/22552047)。開発者本人による、効果とカード固有性、情報伝達、大きく単純な形、既存のタイミングとの同期の説明を参照。今回の適用：四案を別々の素材と抵抗運動にし、同一の被弾時刻で比較する。粒子は追加していない。
4. Riotの旧2017 VFXガイドのURLも調べたが、現在の直接取得はホームページへ転送された。PDFを閲覧済みとは扱っていない。

これらは制作原則の参照であり、各作品の素材や完成エフェクトのコピーではない。

## 他セッションから反映した指摘

記憶の要約に加えて、当日のチャットを読み直した。

- 「ガチャ演出を制作」：冒頭のぼけは一瞬、光が移動してから本を動かす／表紙貫通をなくす／ページの細部を作り分ける／文字の光から結果へ連続させる。今回：衝撃の強いアクセントは80ms以内、カード面は直後から明瞭。カードの枠と素材を一体化し、場に独立物を突然置かない。
- 「呪術師召喚エフェクトを6案制作」：他の採用演出の品質確認、召喚アニメーション前に生カードが出ないようにする。今回：開始から単一のカードDOMと時計を使い、差し替え画像・二重のカード像を作らない。耐久なので元カードは終始残す。
- 「選ばれし4種の召喚演出を制作」等の以前の指摘：面を盤面と平行に扱う、二重発火を避ける、カードアートの安易な別物への流用を避ける。今回：実カードの子として描画するため同じ盤面射影に追従。絵柄を別の魔法オブジェクトのテクスチャには使わない。

## 時間と所有権

- 0–380ms：静止。
- 380–720ms：既存攻撃の構え・踏み込み。
- 720ms：命中、体力1・気合−1を一度だけ表示。
- 720–1180ms：材質ごとの抵抗・接合・復元。
- 1180–2320ms：順に収束。透明度だけで同時に消さない。
- 2320–2800ms：カードが残った状態を読む。

時間指定で同じフレームを再現する。各カードの `EnduranceRig` はキャンバス1枚を所有し、独自RAF・WebGLコンテキスト・タイマーを作らない。停止して終端へ進める操作では生存結果を維持、リセット／破棄では初期数値・スタイル・アイコンを復元する。比較表示へ戻ると実盤面iframeを解放する。実盤面の読み込みも動的importに分離した。非表示中に比較カードを作り直した場合は、表示後にパッシブの発生源座標を再計測する。

## 検証と見た目の自己評価

機能としてブラウザで確認したこと：

- 4案とも0／719／720／1070／2000／2800msをシークし、命中前の体力9・気合2、命中後の体力1・気合1、0msへの巻き戻しで元に戻ること。
- 実盤面で4案×両陣営、気合1→0。対象ごとにキャンバス1枚で、体力1が残ること。
- 390pxで横はみ出しなし。3体同時・低減モーションでは3体とも体力1・気合1、移動・回転0。
- 相手側の同時発動で隣接カードの領域を覆わないこと。
- ブラウザログのアプリ例外なし。既存盤面の `PCFSoftShadowMap` 廃止警告はある。
- `node tests/guts-four-lifecycle.mjs`：4案×3カウンター数×2方向の24ケースで、非表示からの復帰・重複消費防止・無効発火・低減・終了・リセット・破棄復元を確認。Canvasは座標・所有権検査用の代替実装で、見た目の合格判定ではない。
- クライアント型検査と比較版ビルド。ビルドには既存盤面を含む大きなチャンクの警告がある。

見た目の自己評価：4案は亀裂／繊維／鋼板／薄膜で識別できる。絵柄と数値は維持できている。小さい盤面では細い線が弱いため、線幅を最大2.4倍まで補正した。相手側の押し込み方向と展開順も反転した。これは制作者の判断であり、ユーザーの選定・承認を意味しない。

# 01 白亜の築城 — カードの表示を保ったまま演出を終了する

2026-10-15。ユーザーは01の方向を選好し、演出終了時に解像感・サイズ・彩度・枠が変わる繋ぎ目だけの修正を依頼。今回もローカル比較ページの変更。ゲーム本体への採用・公開は含まない。

## 原因

従来の実盤面プレビューは、別途作ったCASTLEのカード面を768×1200の画像にしてWebGLで表示し、終了時に盤面のDOMカードへ戻していた。この別経路では画像解像度・CSSのフィルター・枠や状態表示・文字の描画が完全には一致しない。さらにChromeの合成レイヤーが変わると、DOM自体も描画解像度を変える場合がある。

## 変更

- 01の実盤面では、盤面上の同じカードDOMを召喚中から終了後まで保持。画像カードとの交換もクロスフェードも行わない。
- 手札からの移動・浮上では同じ投影行列をDOMへ適用し、着地後は通常のレイアウトのまま表示する。
- WebGLは石材とその影を担当。カード面は色を書き込まない奥行き判定面として残し、背面の厚み用メッシュは描かない。
- ネイティブ盤面と透明な演出を合成上分離し、カードのレイヤーも保持する。
- 白亜の築城の石材、主動作、時間設計は維持。比較スタジオの描画と02〜04のカード描画経路も維持。

## 検証方法

`check.mjs` はDPR 2、1280px/390px、両陣営、明暗の8条件で、2450・2599・2600msのカード領域の画像と位置を比較する。ピクセル比較中だけ無関係なCSS待機アニメーションを停止し、陣営や背景の変更後に描画の準備時間を置く。召喚の時計はそのままシークする。

移動途中5時刻での中断・復元、3枚同時、低減モーション、02〜04の従来表示も確認する。機能・画像一致は視覚的な最終承認を代替しない。

## 結果

- 8条件すべてで2450/2599/2600msのカード領域のPNGがバイト単位で一致し、矩形位置も一致。`qa/report.json`。
- 途中中断5時刻、3枚同時、低減モーション、02〜04の終了復元に合格。ブラウザー例外0。
- 通常速度の手札移動〜終了を`qa/normal-speed.mp4`に保存。CSS待機アニメーションの停止は行っていない。
- 専用TypeScriptチェック成功、`git diff --check`成功。
- 01の石材が全て消える2440ms以後は、空のWebGL画像の転写も行わない。カードには最終フレームでのスタイル変更を加えない。
- Viteビルド成功（既存の共有Three.jsチャンクサイズ警告のみ）。

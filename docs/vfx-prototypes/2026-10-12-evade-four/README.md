## 回避と攻撃の接続条件

現行`client/src/shared/engine.ts`の攻撃処理では、回避対象のダイスを振り、4以上なら攻撃回数を消費してreturnする。成功時に`attack`イベントを追加する経路は通らない。`client/src/game/controller.ts`は`dice`と`attack`を個別に再生する。

比較フィクスチャはその意味に合わせ、成功は700msの回避→攻撃無効。失敗は弱い予備動作→700msから既存`attackPlan`/`attackPose`/`drawAttackVisual`の通常攻撃を再生する。ダイス値は5/2の固定例であり、サーバーの判定ではない。実盤面の外観には`GameView`と`projectedPlacement`を利用。

採用時は同カードが複数体あるケースを扱える防御側UIDをイベントに持たせ、ダイスと攻撃の間で700msをawaitする専用経路を追加する必要がある。今回そのゲーム本体の変更やデプロイは行っていない。

## 実装と検証範囲

- 四つの独立した頂点変形と表面表現。カード以外の汎用粒子システムは使わない。1つのWebGLコンテキストを共有し、7枚の表面をキャッシュ。実盤面は各対象付近だけのバッファを描く。
- 1体のネイティブカードを1体のメッシュ表面へ置換。0/700msでは元のカードをそのまま表示。停止、表示切替、非表示、破棄で復元。
- `?qa`の「機能検証を実行」はレンダリング差、実盤面両陣営、終端、3体同時、中断、成功時の攻撃抑制、失敗の699/700ms境界、低減モーション、資源数を調べる。
- 「比較動画を記録」は同じレンダラーと実時間RAFから4案の連続再生を記録。書き出し映像とブラウザでの実測フレーム間隔は分けて扱う。
- ローカル比較の動作確認と見た目の自己評価は、ユーザー承認・本体採用・認証済み対戦・ステージング・実機スマホ性能保証ではない。

## 自己レビューで修正した点

- Three.js内蔵関数と同名だったシェーダー関数を固有名に変更し、実ブラウザのコンパイルエラーを解消。
- 高さのあるカードの影が硬かったため、輪郭の透過を周辺サンプルして柔らかくした。
- フィクスチャのスターターカードは`STARTERS`から取得するよう修正。ダイス失敗時に「停止」を押しても通常攻撃の開始点へ戻らないよう、停止先をシーケンス末尾に統一。
- 共有のカード表面キャプチャが能力アイコン画像を含めていなかったため、今回の描画面へ実アイコンを補完。変形中だけ能力表示が消える切り替わりを修正。盤面は通常サイズのカードを使うため、能力表示の位置も`presentation.css`の下端7%へ合わせた。
- 静止画で4案の最大変形を比較し、通常速度録画の連続フレームで溜め、主動作、復帰を確認した。PC実盤面の両陣営と390px実盤面、320pxの横はみ出し・縦スクロールを確認した。

見た目の自己評価：4案は移動、ひねり、屈折、沈潜として区別でき、情報を読むための700msという短さに収まる。これを商用タイトルと同等と断定したり、ユーザー承認済みと判定したりはしない。

## 最終結果

能力アイコン補完後に再確認し、**163/163機能項目を通過**。全体のTypeScriptチェック、追加ファイルを対象にしたTypeScriptチェック、専用Viteビルドが成功。ビルドの大きいチャンク警告は既存盤面／Three.jsを含むプレビューのバンドルに対するもので、コンパイル失敗ではない。

録画は`qa/four-real-time.mp4`、`qa/four-real-time.webm`。最終録画では6秒間に388回の描画、RAF間隔p95=20.9msを観測（録画中の4案同時描画、ローカル環境）。これは実機スマホや対戦全体の60fps保証ではない。代表フレームは`qa/four-peak.png`、連続フレームは`qa/contact-sheet.jpg`。機能記録は`qa/report.json`。

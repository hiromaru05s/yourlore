## 制作前の調査

### プロジェクトの指定と他セッション

- `docs/animation-quality-benchmark.md`、`docs/vfx-art-direction.md`、`docs/world-bible.md` を着手前に確認。「銀紋の流墨」動画を6fpsの連続フレームとして展開し、カード面の細部から主形状へ連続する点、細い明部と暗い芯、短い到着反応を観察した。凍結された原案には変更なし。
- 「吸血鬼召喚エフェクト6種を制作」：2026-10-12 の「1パターンを使い回した6パターン」「牙がマークに見える」「カードフレームの一番上と下にきていない」というユーザー発言を直接確認。形容詞の違いではなく、変形関数・主形状・動作方向を分ける。
- 「商人3種の召喚エフェクトを制作」：「すごく整頓された落ち方」「もっと自然に跳ねる」「下スクロールできない」を直接確認。岩のサイズ・角度に固定した非対称性を与え、破片は接触後の少数に限定。ページはゲーム用のスクロール禁止を引き継がない。
- 過去の呪術師の指摘：突然別物が出る、粒が大きくチープ、フレームスキップ、カードを立てて着地させる。元カードのUVを保持した面を変形し、面を盤面と平行に保つ。

### 対象固有の調査

- `client/src/shared/cards.ts`：`DUNGEON`、コスト2、攻撃0、体力3、`aura: dungeon`。召喚演出にルール上存在しない攻撃・破壊・バフの情報を追加しない。
- `docs/card-art-releases/2026-09-10-theme-identity/revision-log.json`：以前の宝箱表現は却下。坑道自体が生き物。石の牙・琥珀色の眼・線路・湿った支保工が固有の形。箱、舌、携帯できる家具を使わない。
- 既存 `DUNGEON.webp` を目視。岩肌の一部分だけを立体岩の拡散テクスチャに使用。カード絵全体を新しい独立画像として出現させない。
- 召喚経路は `anim.ts` の手札経路 → `flyIntoSlot` → `playMonster`、効果召喚の `summonIn` → `playMonster`。比較では単一時計で描画し、汎用召喚を重ねない。採用時には専用イベント所有と時刻0の元カード隠蔽が必要。

### 一次資料からの学習と翻案

1. [Blizzard / Developer Insights: The Art Behind THE SCIENCE](https://news.blizzard.com/en-gb/article/22552047/developer-insights-the-art-behind-the-science)。Senior Effects Artist本人の解説。主動作のキーフレームを中心に細部を重ねること、カード固有の色・素材・形との結びつき、大きく直接的な形で関係を伝えることを参照。今回の翻案は、粒子を主役にせず、坑道の四つの動作を先に作ること。
2. [Riot / Visual Effects](https://www.riotgames.com/en/artedu/visual-effects)。満足感と盤面の可読性、発生源への帰属を両立するという教材本文を確認。岩の主面・暗い内部・細い亀裂の明部を分け、周囲のカードや盤面全体に光を広げない。
3. [Disney Animation / Animation](https://www.disneyanimation.com/process/animation/)。重量、予備動作、タイミング、後追い動作の公式制作説明を確認。吸気の溜め→主変形→順序を付けた収束を各案へ翻案。
4. [GDC / Artistic Principles of VFX](https://gdcvault.com/play/1024439/Visual-Effects-Bootcamp-Artistic-Principles)。Blizzard／Riotによるケーススタディの概要を確認。講演映像の視聴済みとは扱わない。旧RiotスタイルガイドURLは現行トップへリダイレクトしたため、本文を読めた上記教材を根拠とした。

調査資料の内容と本試作の設計判断は別物。商用ゲームと同等品質という評価や、参照元内部の実装方式の推測は行わない。

## 4案の違い

|案|主形状|固有の運動|終わり方|
|---|---|---|---|
|01 坑口の目覚め|上下の岩顎、石の牙、細い眼|カード面が二つの顎に連続し、一度だけ開く|上下が噛み合い、岩が面へ沈む|
|02 果てなき坑道|多層の岩壁と奥の灯|中心が沈み、地層が奥行き方向に伸びる|内側の層から時間差でせり戻る|
|03 岩盤の呼吸|面を覆う稜線と岩板|カード面が山形にうねり、隆起が伝播する|重量が麓へ伝わって面全体が鎮まる|
|04 坑脈の進行|線路と複数の支保工|カードが前進し、岩の支保工が順に立ち上がる|後方から支保工と線路が畳み戻る|

同一の素材パレットで比較し、色違いで案数を増やしていない。いずれも3秒。同じ時計と同じ実カード面を使用。

## 実装と限界

- Three.jsの立体メッシュ、実カードDOMからのキャプチャ、岩肌テクスチャ、凹凸、細い発光亀裂。独自の画像生成や外部素材の転載はなし。
- 4案はWebGLレンダラーを1つ共有。表示キャンバスへコピー。メッシュとテクスチャを再利用し、フレームごとの新規メッシュ生成は行わない。
- 再生は決定論的な時刻指定。最後は元カード面へ戻る。無関係な輪や全画面フラッシュは使用しない。
- 盤面は `GameView`／実カード／実レイアウトを使った固定状態。手札クリックは比較用の再生トリガーであり、エンジンの正規召喚や認証済み対戦の証明ではない。
- 盤面オーバーレイはDOM矩形に合わせた描画。採用時は正規ランタイムの投影行列・AbortSignal・リプレイ経路へ接続し、改めて一致確認が必要。
- 音声は今回未制作。WebGLが使えない環境は準備失敗を明示する。低減モーションでは静止したカードを維持。

## 検証と見た目

`check.mjs` はブラウザでジオメトリの有限値、通常終了、反復、低減モーション、実盤面の両陣営×1/3枚×4案、手札移動、中断復元、リサイズ、320/390/844px、ブラウザエラーを確認する。

`record.mjs` は実時間のrequestAnimationFrameから4案を連続収録する。`qa/comparison-continuous.webm` と変換したMP4、代表フレーム、実盤面／モバイル画像、report.jsonを保存する。

見た目の自己確認：初稿で粒状に見えた岩を不規則な塊と岩板へ変更。潰れていた坑道の内部は深さ順を修正。有限値テストで見つかった境界の浮動小数点誤差をクランプした。機能検証が通ったことと、ユーザーの見た目承認は別。4案とも選択待ち。

### 最終調整（2026-10-13）

- 初回の岩表示で発生したシェーダーコンパイルの遅延を、再生前の4案ウォームアップで処理。
- 他の比較プレビューとViteの依存キャッシュを共有しない専用設定。盤面で必要になるthreeの追加モジュールも事前準備。
- リサイズ時に子盤面が復元された直後、親が古い時刻を送り直す競合を修正。リサイズは親子とも終了・復元する。
- ④の線路の長さを抑え、隣のマーケットカードとの重なりを軽減。
- 型検査は専用tsconfig、ビルドは専用Vite設定で実施。依存先を含む型検査は成功。ビルドは成功し、Three.jsを含む比較用チャンクにサイズ警告あり。正規ゲームバンドルには追加していない。

最終結果：52/52項目成功、ブラウザpage error 0、型検査成功、専用ビルド成功。`qa/mobile-board-active.png` は390pxで1350msの実盤面を停止した画像。`qa/preview-page.png` は比較ページ全体。最終の連続収録はウォームアップ済みで約3.5秒を取得し、30fpsの動画に保存した（全端末でのフレームレート保証ではない）。

検証用Playwrightはプロジェクト依存を変更せず `/tmp/lore-dungeon-qa` に配置。再準備は `npm install --prefix /tmp/lore-dungeon-qa playwright`。Chromeを使用するため別途ブラウザダウンロードは不要。

連続フレームの最終確認で、坑口の暗部がカード外へ先に見える部分を縮小し、岩肌の展開に合わせて内部の暗さが立ち上がるよう調整した。

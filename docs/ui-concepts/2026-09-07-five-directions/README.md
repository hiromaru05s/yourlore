## 5案の違い

| 案 | 主な設計判断 | リッチさを作る場所 | 複雑さを減らす方法 | 主な検証課題 |
|---|---|---|---|---|
| 01 競技盤 | 上下対戦・中央12枚の水平列・枠なし | 大きいカード絵、数値、控えめな選択光 | 場・市場・手札を帯で分離 | 画面幅が狭いと市場のカード名が小さくなる |
| 02 閲覧机 | 機能を本・栞・紙束として表す | 触覚的な紙と木、影、移動演出 | 同じ物に表示と操作を集約し機能名を併記 | 素材の濃さが可読性を下げないか |
| 03 中央書架 | 左右対戦・市場を中央縦パネルに集約 | 整った書架、アート、余白 | 市場比較を縦の一領域で完結 | 7体時の横幅、左右対戦への習熟、縦画面での再配置 |
| 04 召喚舞台 | 場札を立ち上がるイラスト＋数値台座で表す | 各カードの存在感と限定的な発光 | 飾りを背景ではなくプレイ対象に集中 | 7体時の重なり、対象の当たり判定と選択範囲 |
| 05 白い整理盤 | 各者7+7枠を薄く明示 | 白い素材、カード絵と字組みのコントラスト | 空き容量と場の分類を説明なしに理解 | 枠が情報より目立たないか、手札との干渉 |

01 は競技用途の実装候補、02 は LORE の書庫らしさを育てる候補。03 は市場中心の構成を検討する比較案、04 は存在感の比較案、05 は学習しやすさの比較案。優劣は実機での7体・7枚満杯状態や小画面を検証して決める。

## 共通の操作フロー

1. **カードを読む**: カードをタップ/既存の拡大操作 → 詳細。画面上の小さいカードに全文を詰め込まない。
2. **購入する**: 現行のタップで拡大、ダブルタップで購入準備、続くタップで購入という安全機構を維持。確認をカード直近の短い表示にまとめる。価格は購入時の実効コスト。購入後は墓地へ。
3. **使う/攻撃する**: 手札を場へドラッグ、自分の場札から攻撃対象へドラッグ。候補だけ強調。自分の場の内部へのドラッグは並べ替えとして区別。
4. **手番を終える**: 残秒を伴う終了操作。手札が6枚以上なら超過分の破棄選択へ進む。通常盤面に破棄ボタンを常設しない。
5. **補助情報を見る**: 山札/墓地/除外/ログを必要時に開き、閉じると元の盤面と選択文脈へ戻す。

## 実装時の判定条件

- 2者 × (モンスター7＋魔法罠7) の満杯状態で全部を選択できる。
- 固定8＋提示4枠は中央からサイドパネルへ移動しない。縮小や購入済みは空き状態として表す。
- 提示の所有者と更新対象が明確。固定市場に通常更新操作があるように見せない。
- 単なる色替えで終えず、5案の判断構造・物の表現・情報配置の差を保持する。
- 新しいヒーロー能力、通貨、クエスト、攻撃一括ボタン、独立した罠7＋魔法7などは追加しない。
- 画像生成の細字/カード本文は実装仕様ではない。全数値・翻訳・カード名・効果はデータから描画する。
- 7体＋魔法罠7、手札多数、最大マナ30、無料更新、提示空き、長い日本語/韓国語/英語、被ダメ/孵化/カウンター重複、再接続を実機で確認する。静止画だけでUXが検証済みとはしない。
